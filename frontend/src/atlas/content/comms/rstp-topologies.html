Switching

  • A loop without RSTP is a broadcast storm. RSTP keeps one path alive and holds the spares blocked until a failure.
  • Engineer the root bridge — set a low priority on your chosen root and backup root, or the network elects one by lowest MAC and you get whatever that is.

Sizing

  • Topology by size: ring ≤ 5 switches, ladder for 6–10, extension ladders for geography — and split the Layer 2 domain around 100–200 end devices.

1Loops and RSTP

Redundant paths mean loops, and a switched loop with no protocol is a broadcast storm — frames circulating and multiplying until the network chokes. RSTP's job is to keep exactly one active path between any two points and hold the spare links blocked, then unblock them when a working link dies (reconvergence).

Traffic between SW4 and SW3 takes the long way while all links are healthy; the moment the top link dies, the blocked link opens and the path flips. ▶ Animated in the HTML edition.

  • Root bridge selection is yours to engineer. Lowest bridge priority wins (default 32768, range 0–61440); a tie falls to lowest MAC address — i.e., a random switch. SEL's guidance: deliberately set a root and a backup root with low non-default priorities, and remember SEL switches log every root change.
  • Hops are bounded: Max Age (6–40, default 20) is how many hops from the root a BPDU stays valid. Deep topologies and dual-connected rings can balloon hop counts after a failure (AG2017-21's example: 2 hops before, 11 after) — reconvergence and latency suffer.
  • Topology guidance (AG2017-21): ring for ≤5 switches, ladder for 6–10; keep IED-to-IED hop counts small.
  • Edge ports: set switch ports feeding IEDs to fast/edge mode so they forward immediately instead of waiting out RSTP transitions — and enable BPDU Guard on ports facing non-RSTP gear.
  • SDN is the other answer (SEL-2740S + SEL-5056 Flow Controller): deny-by-default, every conversation an engineered OpenFlow entry, no MAC learning or spanning tree, failover paths pre-planned for sub-millisecond healing, and flows persist even with the controller offline. Different philosophy: RSTP discovers a topology; SDN is told one.

2Choosing a topology

AG2017-21's sizing rules, condensed. The driver is always hop count between end devices — hops set both latency and how ugly reconvergence gets.

Blocked links (dashed) are the reserve capacity — RSTP holds them Discarding until a failure. Highlighted links pulse in the HTML edition. ▶ Lightly animated in the HTML edition.

  • Ring for five switches or fewer — few hops, quick convergence, cable-efficient. The RSTP standard technically allows a 40-node ring; don't — reconvergence time and hop count make big rings unfit for anything mission-critical.
  • Ladder for six to ten — two rails (root and backup root at the top), rungs as normally-blocked cross-links ready to activate. A 10-switch, 4-rung ladder of 24-port switches yields 200+ usable ports.
  • Extension ladder when geography forbids home-run cables — join local ladders, and consider a Layer 3 boundary as the network grows: SEL's guidance is to keep a Layer 2 domain to roughly 100–200 end devices before segregating into subnets (see IP Addressing, Gateways & DNS in atlas).
  • On the SEL-2730M, use the SFP ports (1–4) for switch-to-switch links — first-priority in SEL's port plan, with copper 9–24 as fallback; ports 5–8 are better kept for normally-blocked backup links than primary trunks.
  • Avoid casually dual-connecting rings: the AG's real-world example went from 2 hops between relays to 11 after a single link failure. Interconnect deliberately, near the roots.

3Troubleshooting & fine print

  • Whole-network stutter after a cable move → a loop closed somewhere RSTP isn't running (or was plugged into edge/BPDU-guarded ports). Broadcast storms look like everything failing at once.
  • Random switch is root → nobody set priorities; the lowest MAC won the election. Engineer root + backup root, and watch the root-change logs after any network event.
