☰The rules, stated plainly

Substation time

  • IRIG-B is the workhorse. A GNSS clock decodes satellite time and distributes a 1-second, 100-bit pulse-train frame. SEL relays accept demodulated IRIG-B only — modulated (1 kHz sine) needs a demodulator first.
  • One IRIG input at a time. On the SEL-751/751A: terminals B01/B02, PORT 3 (EIA-232), or fiber PORT 2 — pick one, then set TIME_SRC to match (IRIG1 for the first two, IRIG2 for PORT 2).
  • Accuracy is a ladder: demodulated IRIG-B / PTP ±100 ns · modulated IRIG-B ±1 µs · NTP/SNTP ~milliseconds. Synchrophasors need a source good to ±10 µs or better — SNTP can never carry them.
  • The IEEE C37.118 control-bit extensions (bits 50–78) carry year, leap second, DST, local offset, and time quality. Set relay IRIGC := C37.118 to use them.
  • Coax distribution is a 50 Ω daisy chain, ≤152 m (500 ft), terminated at the far end. Beyond that: fiber (SEL-3405, ≤4 km, <200 ns added).

1Why the substation needs one clock

Every relay keeps its own time-of-day clock; unsynchronized, a typical relay drifts about 2 minutes per year (SEL-751 and 751A specs alike). That is fine for a front-panel display and useless for anything comparative: lining up SER records and event reports across relays after a fault, feeding a communications processor a coherent sequence of events, or measuring synchrophasors, where the phase angle is taken against an absolute time reference and every microsecond of clock error is electrical degrees of lie. The fix is one accurate source, distributed to everything.

The SEL-751A ranks its sources: while IRIG-B is present and valid (Relay Word bit IRIGOK or TSOK asserted), the relay follows IRIG-B even if SNTP is configured and a server is answering. Only when both deassert does it fall back to the NTP server. SNTP is a backup, never a peer. The SEL-751 — which, unlike the 751A, also speaks IEEE 1588 PTP on Port 1 — extends the ladder: hardware-assisted PTP → IRIG-B → firmware PTP → SNTP → everything else (DNP, IEC 103, Modbus, TIME/DATE commands).

2IRIG-B on the wire

IRIG-B is a serial time code: a 1-second frame of 100 bit slots, 10 ms each. Every slot carries a positive pulse whose width is the data: 2 ms = binary 0, 5 ms = binary 1, 8 ms = position identifier (P0…P9, one every ten bits). Two 8 ms markers back to back mean the frame is starting — the rising edge of the reference bit Pr coincides exactly with the seconds change. Between markers, the frame spells out seconds, minutes, hours, and day-of-year in BCD, least-significant bit first.

The relay decodes each field as the pulse train arrives; BCD digits accumulate between position markers and the decoded time latches at the markers. The frame continues through hours, day, and the C37.118 extensions. ▶ Animated in the HTML edition.

Demodulated vs. modulated, and the format codes

  • Demodulated (unmodulated) IRIG-B00X — the pulse train as a DC level-shift TTL signal (5 V nominal). The precise one: ±40 ns average / ±100 ns peak to UTC from the SEL-2488, and the only kind SEL relays accept directly.
  • Modulated IRIG-B12X — the same frame amplitude-modulated onto a 1 kHz sine carrier (mark 1–6 Vpp, mark-to-space ≈3:1; SEL-2488 output 6.2 Vpp nominal). Long-haul-tolerant but only ±1 µs peak — and a relay can't read it. The SEL-IDM converts modulated → demodulated (11 TTL outputs; the IDM 000-1 variant buffers already-demodulated code).
  • Last digit = coded expressions. B002/B122: bare time frame — no year, no control bits. B004/B124: extended frame with IEEE C37.118.1-2011 control bits, backward compatible with B000/B120 and the 2005 edition. SEL-2488 default output is IRIG-B004; even/odd parity is one global setting for all extended-format ports. If a legacy device chokes on BXX4, drop that port to BXX2.

Other extension bits: year in BCD (50–58), leap-second pending/type (60–61), DST pending/active (62–63), local-time offset sign + hours + ½-hour (64–68, 70), parity (75). SBS = 17-bit straight binary seconds-of-day (80–97).

Time quality is not decoration. A clock in holdover keeps sending IRIG-B — it degrades the TQ/CTQ bits as its oscillator drifts. A relay set IRIGC := C37.118 reads them and drops TSOK when the source is no longer synchrophasor-grade; a relay set IRIGC := NONE ignores them and trusts a drifting signal.

3Distributing the signal

Demodulated IRIG-B is distributed on 50 Ω coax as a daisy chain: out of the clock, into each device, on to the next, with a 50 Ω terminator at the far end of the chain. RG-58 runs up to 152 m (500 ft) from output to last device; lower-loss cable (RG-8X) stretches that. Each SEL-2488 BNC output drives 250 mA at 5 V — typically 10 low-impedance or 20 high-impedance devices per output (700-series relays like the 751A are high-impedance; 300/500-series and SEL-2030/2032 are low). Don't mix impedance classes on one chain, and skip the external terminator when five or more low-impedance devices already load the line.

One clock, three transports. The sync ripple: the top-of-second edge leaves the SEL-2488 on every output simultaneously; each path adds a known, compensated delay. ▶ Animated in the HTML edition.

  • Cable delay compensation, per port: 0–2500 ns of output-cable compensation per SEL-2488 port (default 10 ns) — RG-58 is 5 ns/m, RG-8X 3.87, LMR-240 4.17 — plus antenna-cable compensation on the GNSS input. Group IEDs by location per port; compensate for the average run.
  • Fiber for distance and isolation: the SEL-3405 T/R pair carries demodulated B000/B004 over multimode fiber up to 4 km with <200 ns added — but only with both fibers connected (the return link measures propagation delay for auto-compensation; one fiber = uncompensated pass-through). No settings; DB-9 powered (15 mA). Cap unused ST connectors — reflected light reads as data.
  • The DB-9 output is not a coax output: SEL-2488 COM1 IRIG pins drive 5 mA over ≤3 m — it feeds a 3405T or one nearby device, not a chain.
  • Redundancy: an SEL-3400 distribution module takes two IRIG-B inputs (e.g., local SEL-2488 + ICON ring), compares them continuously, and forwards the better time quality.

4The clock itself: SEL-2488

The SEL-2488 tracks GPS L1 C/A (1575.42 MHz) and GLONASS L1 (1602 MHz), up to 16 satellites each. It will not lock — and will not enable any output — until it qualifies the signal: at least 4 satellites Used at ≥30 dB-Hz per active constellation. Warm start ≈240 s; cold start adds up to 12.5 min of UTC compensation download, and output enable after a restart can take up to 15 min. Gating is deliberate: no time out until the time is known good.

Holdover — losing the sky

On GNSS loss the clock enters holdover: outputs keep running from the internal oscillator, and the IRIG TQ/CTQ bits, PTP clock class, and NTP fields all degrade honestly as drift accumulates. Typical error after 24 h of holdover (unit warm ≥24 h first):

Holdover requires prior sync with no power interruption since. Enable Holdover Alert (default on, 0–120 min pickup delay) to raise a major event when it happens.

Spoofing & diagnostics

  • Satellite Signal Verification (SSV): with the dual-constellation antenna (SEL-9524B), the clock cross-checks GPS against GLONASS. Failure action is settable: notify-and-continue (default) or notify-and-stop — the latter drops straight into holdover on anomaly.
  • Antenna monitoring: the +5 V antenna feed is supervised — Antenna Short (excess current: shorted cable, too many splitters) and Antenna Open/Absent (no draw: cut or disconnected cable) events.
  • Front panel: ANTENNA STATUS (red = missing/shorted), SATELLITE LOCK (amber = enabled, not locked), TIME QUALITY (green <1 µs, flashing green <1 ms, red ≥1 ms).
  • Antenna cable delay compensation: 0–2500 ns (LMR-400 ≈ 3.92 ns/m).

5Network time: NTP/SNTP vs. PTP

Both ride Ethernet; they are not the same class of thing. NTP measures round-trip delay in software and gets you milliseconds. PTP (IEEE 1588-2008, V2 only — V1 is incompatible) timestamps packets in hardware at the PHY and corrects for switch residence time, getting you the same ±100 ns class as demodulated IRIG-B — if every device and switch in the path plays along.

SNTP is a "set the clock" protocol, not a measurement one. The SEL-751A's spec with SNTP is ±5 ms (typically better than ±1 ms with a single switch between relay and server, UNICAST/MANYCAST); the SEL-751's 2026 spec states ±1 ms in an ideal network. Fine for logs; orders of magnitude short of synchrophasors. PTP needs the whole path engineered — one dumb switch in the middle quietly eats the accuracy budget.

Relay Word bits that tell you the truth

  • IRIGOK — IRIG-B input data is valid; relay time is following IRIG-B.
  • TSOK — time is based on an IRIG-B source of sufficient accuracy for synchrophasors (751: IRIG-B or hardware-based PTP). MET PM refuses to run with TSOK = 0; the front-panel/report header flips between Time Source: Internal and External.
  • TSNTPP / TSNTPB — synchronized to the primary / backup NTP server. PMDOK — relay enabled and synchrophasors enabled (EPMU := Y). DST — daylight-saving active. 751 adds PTP_OK/PTPSYNC/PTP_TIM (valid PTP source · within local-offset tolerance · actively syncing) and PTPA/PTPB for PRP/HSR port health.

SymptomLikely cause / fix
Relay never syncs, clock is finePolarity swapped on B01(+)/B02(−); two IRIG inputs wired at once (only one allowed); TIME_SRC pointing at the wrong input; or the source is modulated IRIG-B — insert an SEL-IDM or set the clock port to B004. Scope check: TTL pulses 2/5/8 ms wide.
