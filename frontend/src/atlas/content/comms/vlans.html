☰The rules, stated plainly

Switching

  • A VLAN is a separate broadcast domain on shared hardware. Frames never cross between VLANs inside a switch.
  • Access (untagged) ports belong to one VLAN; the attached device never sees a tag and does not need to know VLANs exist.
  • Trunk (tagged) ports carry many VLANs, with an 802.1Q tag on every frame so the far switch knows which domain it belongs to.
  • Do not leave anything on default VLAN 1. Create an unused VLAN and move every unused port into it, untagged.
  • The tag carries priority as well as identity. Three priority bits (802.1p) are how GOOSE and sampled values get ahead of SCADA traffic in a switch queue.
  • VLANs segment broadcast, not routing. Two VLANs that must talk still need a router or a Layer 3 interface between them.

1One switch, many networks

A VLAN slices a broadcast domain out of shared switch hardware. Two rules carry the whole topic: an access port belongs to exactly one VLAN and its device never sees a tag; a trunk port carries multiple VLANs, tagging every frame so the switch at the other end can keep them apart.

This is why VLANs are attractive in a substation: one physical network, several logically separate ones, without pulling more fiber. (Animated in the browser.)

2What is actually in the tag

An 802.1Q tag is four bytes inserted into the Ethernet frame after the source address. Knowing its fields makes both VLAN and GOOSE troubleshooting far quicker.

Priority and VLAN ID travel together. That is why a GOOSE configuration asks for both, and why a switch that strips the tag also strips the priority. (Animated in the browser.)

Do not use default VLAN 1. SEL's switch-security guidance is explicit: create an unused VLAN and move every unused port into it, untagged. A port left on VLAN 1 shares a broadcast domain with everything else that was never moved, and it is an open invitation for denial-of-service and VLAN-hopping mischief. Set the native VLAN on trunks to something unused as well.

4Designing the segmentation

A substation VLAN plan is usually organized by function, because that is what the security boundary follows.

Station bus / SCADARTAC to IEDs, and RTAC northbound. The operational data plane.
Process bus / GOOSEMulticast protection traffic. Tagged with high priority and confined to the ports that need it.
Engineering accessLaptops and jump hosts. Reaches devices through the gateway, not by sitting on the same VLAN as SCADA.
ManagementSwitch and device management addresses, syslog, and monitoring.
TimeSometimes separated, particularly where PTP is in use and its traffic profile matters.
Unused / parkingEvery unused port lands here. Not VLAN 1, and not routed anywhere.
  • Keep the plan documented alongside the IP plan — a VLAN ID with no recorded purpose becomes untouchable.
  • VLANs are not a substitute for a firewall. They separate broadcast domains; they do not inspect traffic or authenticate anything.
  • Do not over-segment. Every VLAN that must talk to another needs a routed path, and each routed path is a place for a mistake. Segment where there is a real boundary.

5GOOSE and priority

  • GOOSE frames carry a VLAN ID and a priority. On the RTAC the defaults are priority 4 and VLAN ID 0 — VLAN ID 0 meaning the tag is present for its priority but the frame belongs to no VLAN.
  • The tag is how you confine multicast GOOSE. Without VLAN membership control, a multicast GOOSE frame floods every port in the broadcast domain, wasting bandwidth on devices that do not subscribe. With it, the frame reaches only the ports that need it.
  • Priority is how GOOSE jumps the queue. A switch under load queues frames; a higher PCP value gets served first. On a network carrying protection traffic alongside file transfers and SCADA polls, that ordering is the difference between deterministic and merely usual.
  • Both ends must agree. A publisher tagging VLAN 100 and a subscriber whose port is not in VLAN 100 will simply never receive the frames — and GOOSE supervision will report the subscription as lost. See IEC 61850 & GOOSE.

6Troubleshooting & fine print

  • Device reachable from some ports and not others → VLAN membership mismatch: the port you are on is not in the device's VLAN, or the trunk between switches is not carrying that VLAN.
  • Works locally, fails across the trunk → the VLAN is not allowed on the trunk. Trunks carry only the VLANs configured on them.
  • Untagged traffic appearing in the wrong VLAN → native VLAN mismatch between the two ends of a trunk.
  • GOOSE subscription lost after a network change → VLAN membership or tagging changed on the path. Capture on the subscriber's port and look for the tag.
  • Everything works but nothing is prioritized → a device or a hop is stripping the tag, taking the priority with it.
  • A new device cannot be reached at all → the port was never moved out of the parking VLAN. This is the intended behavior, and it is worth confirming before assuming a fault.
  • VLANs segment broadcast, not routing. Two VLANs that must talk need a router or a Layer 3 interface, which brings the gateway rules back — see Ethernet & IP Addressing.
