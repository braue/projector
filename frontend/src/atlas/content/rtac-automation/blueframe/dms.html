☰The rules, stated plainly

DMS

  • DMS is modular by feeder, deliberately. Functionality is configured, tested, and commissioned one feeder at a time, so the first feeder and the hundredth are equally simple. Each configured feeder communicates with its electrically adjacent feeders to locate faults and calculate restoration.
  • Three applications, in order: MDI consumes your GIS or CIM files, PSM holds the SEL DMS model, and FLISR runs on it. PSM must be installed alongside FLISR.
  • FLISR locates faults from Boolean fault indications, not from measurements. Voltage is used optionally to confirm a zone is dead; current is used to avoid overloading feeders and to size the load in each segment.
  • Measurement Name is the link to reality. A node whose Measurement Name is unset is assumed to have no Protocol Services connection — and it will not appear in the DMS application at all.
  • Field time synchronization is not optional. Look-backs and measurement validity are based on accurate timestamps.
  • Simulate before you commission. The simulator is built in, runs on a copy of the live feeder, and does not affect the commissioned one.

1What DMS is

The SEL Distribution Management System suite provides wide-area system monitoring, control, and management, emphasizing simplicity, scalability, and security. Its current functionality is Fault Location, Isolation, and Service Restoration: using field data to identify and automatically isolate faults while restoring load from adjacent sources, maximizing system margin and minimizing switching.

This is the argument against monolithic control systems, where settings live in one interconnected place: those are hard to scale and hard to know how much of to retest after a change. (Animated in the browser.)

2Model Data Import

MDI is feeder-centric by design: it calculates distribution and substation connectivity from geographic information and divides it into feeders, which PSM then organizes into substations and regions. It accepts partial models — a single feeder, a substation, a region, an area of responsibility, or any arbitrary bounded area — which is what makes integration into an existing utility system practical.

Input requirements

GIS / GeoJSON

  • Coordinates formatted as WGS-84.
  • Data in GeoJSON format (RFC 7946 §3.1).
  • Minimum assets: Busbar, Circuit Breaker, Disconnect, Elbow, Fuse, Line, Open Point, Recloser, Sectionalizer, Source, Switch.
  • MDI inspects all layers in the file, and inspects each feature — some features become model assets, others exist only to determine connectivity. Which is which is decided by the pipeline.

CIM

  • Data must be IEC 61970-301 compliant. Most CIM data imports without modification.
  • Minimum assets: a substation or transmission line, and a node within it.
  • CIM describes equipment as nodes with attributes and connections; MDI traverses the CIM tree by those connections to construct the PSM model.
  • Supported CIM asset types span Region, Substation, Transmission, Busbar, Capacitor Bank, Circuit Breaker, Current Transformer, Disconnect, Elbow, and Egress Point among others.

Asset types and what they do

AssetRole in the model

Circuit BreakerA distribution substation feeder breaker. Controllable, placed in the model
RecloserA three-phase distribution recloser. Controllable, placed in the model

Duplicate assets across a substation model and a distribution model must be removed from one of them. If a duplicate is not proactively removed, MDI alarms on the duplication — and if you are updating automatically without exporting in a way that avoids duplication, MDI alarms on every delta model update.

The three-step process

  1. File import. Use the Import dialog on the MDI Import Inbox page; select or drop one or more CIM or GeoJSON files. They upload and are inspected for all feature types, property keys, and property values — which is what populates the pipeline configuration controls. Each file in the Inbox must be assigned a pipeline to be used.
  2. Pipeline execution. A pipeline contains the rules for detecting the asset types PSM supports and for determining connectivity. Create one from the dropdown under the Pipeline column, or import a prebuilt pipeline file. For GIS, each feature must belong to one or two feeders — features belonging to two are generally open points connecting different feeders on each side — so provide the correct key values for Feeder1 ID and Feeder2 ID. The optional Asset Designation field prepopulates assets in the left panel to speed mapping. Select files, Assign Pipeline, then Run Pipeline to validate that all pipeline properties match.
  3. Model build. Build Draft populates the feeders so they are viewable in PSM. Draft models are then reviewed and published in PSM.

3Power System Model

PSM breaks everything into feeders, because considering one region at a time drastically reduces the complexity of a power system. A feeder contains breakers, reclosers, and switches, and connects electrically to one or more adjacent feeders — all configured graphically on the feeder canvas.

The canvas

  • An auto-directed layout: each connection point offers a menu of node types to add. The schematic defines layout, connectivity, and settings, all used by DMS applications for operation and display.
  • Link mode connects nodes across canvases — select the target endpoint whether it is on this canvas or another. Once a Link node exists, it becomes a clickable node for quick navigation between the linked feeders.
  • Every feeder needs a device connected to the feeder source (the small transformer in a circle). Select the + on the source and choose the first device type; the expanded menu then adds Junction and Link nodes as well.
  • Every feeder needs a source, a switching device, and a way to mark its end or tie — an End-of-Line, Link, or Placeholder node completes a feeder or branch.
  • Some settings render on the canvas for at-a-glance verification; the Property Grid shows all of them. Model settings are edited by selecting whitespace; node settings by selecting a node.
  • Hot keys cover the whole workflow — Esc exits Link mode, 0 fits the diagram, Ctrl+B toggles keyboard mode, P pan, Space temporary pan, V select, =/- zoom, Shift+1…4 add to the west/north/east/south port, Del delete, Shift+E edit name, Shift+D toggle normal position, Shift+S/Shift+F set left/right PT, Shift+R show or hide junction ports, Ctrl+A select all, A select all of type.

Building hierarchy manually

PSM supports manual model building alongside MDI import: New Region (a regional hierarchy based on customer zones), New Subregion (one tier below a region), New Transmission (a transmission line for substations to attach to), New Substation (for feeders to attach to), and New Feeder (a canvas to draw on), plus a search feature. Any element offers Checkout, Rename, Discard, and Delete on right-click.

An unmapped Measurement Name makes the node invisible. The manual is explicit: this setting must be configured for automation applications to run on SCADA data, the value must match Protocol Services, and if it is not mapped, that node will not appear in the DMS application. When a device you drew is simply absent from FLISR, check this first.

Validation, publishing, and checkout

  • PSM continuously saves and validates as you work, with descriptive feedback for the project, each canvas, and each node in real time. Messages can be filtered by canvas and severity.
  • New feeders, substations, transmission lines, and regions are drafts and appear in the Draft Panel. They are invisible to other Blueframe applications and users until published. Draft changes must be published as a batch; discarding can be done as a batch or item by item.
  • A published canvas cannot be changed without checking it out. Checkout creates an editable draft, removes the canvas from the published branch in the corresponding automation application, and can be held by only one user at a time per canvas (though one user may check out several canvases).
  • A model exported while unpublished is locked to that user — it must be published to be exported and shared with other Blueframe users or systems.
  • The Placeholder node defines a future Link so you can publish and even run simulations before the link exists; it disappears once the additional feeders and links are added.
Changing a commissioned canvas decommissions it. You must then follow the DMS application's commissioning process again before it is considered operational. Plan model edits as commissioning work, not as drawing work.

4How FLISR actually works

FLISR queries each available neighbour during planning to learn how much capacity it can supply through each connection, based on that neighbour's current switch configuration and loading. (Animated in the browser.)

Fault location

  • Detection is driven by a device reporting a Lockout. FLISR then looks for a true Fault Latch/Indication, waiting Event Detection Delay seconds after the lockout to allow enough time for it. After a true fault latch, it validates all other conditions — open/close (52A3P), voltage, current.
  • Location uses Boolean fault indications only, from each breaker, recloser, and switch, regardless of which protective device ended up locking out. FLISR traverses the feeder from the source outward and locates the fault at the longest serial path found, whether or not intermediate devices set their fault latches.
  • FLISR does not use voltage or current for location. Voltage is used optionally to confirm the zone is de-energized; current is used to avoid overloading and to size segment load.
  • The fault binary point (<device>.fault, mapped in Protocol Services) should assert on overcurrent pickup. If relay logic latches it, the latch must be cleared shortly after — about one second — short enough that it does not remain asserted and affect later events. FLISR latches the pickup into its internal OvercurrentReported, cleared after event completion or two minutes, whichever comes first.
  • Total reclosing time for all field devices must be less than 5 minutes.
  • FLISR will not operate for an outage with no fault latch — a manual or non-fault operation is not an event.
  • Cold load pickup and inrush can falsely trigger phase overcurrent elements. SEL recommends implementing cold-load-pickup or inrush detection schemes so re-energization does not generate false fault indications.

Isolation and restoration

  • Isolation: FLISR identifies the boundary devices — the breakers, reclosers, or switches electrically nearest the fault in both the up-line and down-line directions — and issues an open command simultaneously to each that is not already open.
  • Restoration places switching operations into parallel paths according to their electrical dependencies. Isolation always precedes re-energizing a segment, but up-line and down-line switching run in parallel because they are electrically separated by the outage. This also makes FLISR resilient to device failure.
  • Neighbour participation: if a neighbour feeder has FLISR mode and/or Voltage Event mode set to Automatic, FLISR may operate switching devices on that neighbour as part of the plan.
  • Voltage is not used to qualify or prioritize restoration sources — only, optionally, to confirm the fault zone is dead first.

Return to Normal

  • A single control — over DNP3 or from the Return to Normal menu item — makes FLISR issue a sequence returning the feeder to the normal configuration defined by the normal status settings in PSM.
  • Closed transition: no outages, and never more than two feeders connected at a time. Feeders are tied only for the interval between closing one open point and opening another — a duration governed primarily by communications polling intervals.
  • If an unexpected control failure leaves two feeders electrically connected, FLISR re-opens the open point before starting Return to Normal switching, to leave the system electrically safe.
  • Return to Normal will use a neighbour that does not itself have RTN enabled — but a Return to Normal command issued on that neighbour is dismissed.
  • FLISR does not validate phasing between two feeders during Return to Normal. Local devices must validate phasing.
  • RTN fails on an unexpected switch change or an unresponsive device, and is disabled entirely if a feeder's phasing is set to NONE (a loop could be designed), or if a neighbour is de-energized, blocked, disarmed, actively reconfiguring, not enabled, or not found.

Adding a feeder: use the horizontal ellipsis in the commissioning panel. FLISR leverages all imported and manually created models in PSM, scanning for the most-upstream protective device — which may bring in multiple substation assets.

Modes

ModeBehaviour
AutomaticIsolation and reconfiguration using available feeders when an event is detected
Isolation OnlyIsolation only, plus a supplemental advisory report with a recommended switching sequence and adjacent-circuit availability
AdvisoryNo automatic action; generates an advisory report with recommended isolation and reconfiguration sequences and adjacent-circuit availability

A feeder in Isolation Only or Advisory mode cannot participate in restoring a neighbour — with one exception: if such a feeder is feeding an adjacent feeder in Automatic mode such that the open point is a member of the adjacent feeder, that open point may still be operated as part of the neighbour's restoration sequence. The same applies to Return to Normal. Note also that a device closed during a FLISR reconfiguration is reverted during Return to Normal, and shows as an open step in the activity report.

Arming, disarming, and blocking

  • Arm and disarm per feeder, from the interface or over DNP3. The only way to arm a disarmed circuit is to issue an arm command — FLISR never arms itself.
  • FLISR blocks itself per feeder in reaction to device and feeder-level data. Qualifying indications: hot-line tag, remote control disabled, loss of communication, feeder-level FLISR block indications, and device-level FLISR block indications. Operations stay blocked until the indication clears on all feeder switching devices.
  • A disarmed or blocked feeder does neither isolation nor restoration switching, and is unavailable to other feeders needing restoration support.
  • Loops are not supported. When the normally open point is closed and two feeders are tied, FLISR is automatically disabled; opening a device to break the loop exits the condition. If a device opens while in the looped condition, FLISR waits the Event Detection Delay and checks the Fault Latch — if true, it stays in the looped condition because it assumes the device is actively reclosing, and exits only once a lockout is detected.

Device-level overrides

Control InhibitUses all data received from the device, but will not operate it in isolation or restoration
Out of Service OpenIgnores all data from the device, treats it as an electrical open point, and does not operate it
Out of Service ClosedIgnores all data, treats it as an electrical closed point, and does not operate it
Switch with Has Status = FalseTreated as Inhibited, because FLISR cannot verify a device operated without a status update

Return to Normal and out-of-service states interact in a way worth reading twice. RTN operates on feeders with devices in Out of Service Open, Out of Service Closed, or Control Inhibit as long as those devices are in their as-built PSM state. If an out-of-service state does not match the device's as-built open/closed state, RTN will not operate — and if RTN would need to operate a Control-Inhibited device, it will not operate either.

7Simulation

Simulation is tightly integrated: use it to validate settings, build familiarity, and answer "what if" questions. Select Simulate from any open feeder canvas and a dedicated simulation opens in a new browser tab, using a copy of the feeder. Doing this from a commissioned feeder does not affect it — it remains operational and unaffected.

Simulator controls

Arm/Disarm · Reset (returns loads, device status, and fault conditions to initial values) · Fullscreen · Clear Fault Latches · Return to Normal · Target Reset · Populate Load History (makes the active current readings the historical values for the next simulated event).

Simulating a permanent fault

  1. Arm FLISR if you want it to operate.
  2. Configure line loading and adjacent feeder margin in Device Details. Line segments default to 10 A; adjacent feeder connections default to 200 A of availability — adjust either by selecting it and changing the value.
  3. Select the line segment where the fault will be and set Event Trigger. The options are Fault (a fault without lockout), Lockout (full lockout — a FLISR event, applying fault indications to every up-line device and driving the nearest breaker or recloser to lockout), and Open Phase (a voltage FLISR event).
  4. Review the status chips and the canvas — the one-line shows the fault location plus icons with tooltips indicating which devices received open and close controls.

Simulating a miscoordination

Set the line segment's Event Trigger to Fault (fault indications on every up-line device, no protection action simulated), then select the miscoordinating device or devices and choose Lockout in the Device Details pane. Review the result as above.

Testing Return to Normal

Clear the fault conditions with Clear Event on each affected line segment — or leave them and watch FLISR cancel its Return to Normal switching when it encounters a permanent fault — then select Return to Normal from the simulation controls. Note that Reset clears the canvas and all simulator settings are lost.

Let the Event chip clear before running the next test. When FLISR begins processing an event it enables the Event chip; the chip disappearing indicates analysis is complete. Whether you are using the built-in simulator or another system such as a DAC to mimic field data in a QA/QC environment, wait for the chip to deassert before resetting and running the next event.

Report API

  • GET /flisr/api/v1/reports — list of reports with full content. Requires FLISR Can Launch.
  • GET /flisr/api/v1/reports/metadata — report metadata. Requires Can Launch.
  • DELETE /flisr/api/v1/reports — deletes all reports matching the parameters. Requires Can Launch and Can Operate. Deletion cannot be undone.

Every endpoint requires an authentication token per interaction, obtained by POST to /login-page/v1/login; the token nests inside a token object and is valid for five minutes. Full schemas and examples are in the integrated documentation under View → API Documentation.

SCADA data — per device

Binary inputs published to SCADA include OvercurrentReported (the fault latch bit FLISR generates internally), CommAlarm, FlisrAlarm (FLISR has detected a problem with this device), Inhibited, OOSOpen, OOSClosed, CommandFail, and Set1InstrumentationError / Set2InstrumentationError. Binary outputs accepted from SCADA are InServiceCommand, InhibitControlCommand, OOSOpenCommand, and OOSClosedCommand.

SCADA data — per feeder

Inputs: Armed, FieldConditionBlockAlarm, LoopAlarm, EventDetected, PermanentFaultDetected, MiscoordinationDetected, Reconfiguring, ReconfigComplete, ReconfigFail, VoltageEventDetected, and the three subtypes OpenPhaseDetected, InstrumentationError, and LossOfSourceDetected (published in addition to VoltageEventDetected). Outputs: RTN, Arm, Disarm, and FlisrTargetReset. Feeder-level block points appear as <Feedername>.FlisrBlock1 through 5 in the Status Supervisor data.

Two mapping rules that will bite you. All SCADA binary outputs must use the operPulse control model. And ReconfigComplete and ReconfigFail, once asserted, keep their asserted value until a Target Reset is sent or a new FLISR event occurs — so an operator screen that treats them as momentary will look permanently stuck.

10Gotchas

  • A device you drew does not appear in FLISR → its Measurement Name is blank or does not match Protocol Services.
  • The fault binary point stays latched → later events are affected. Clear it in relay logic roughly a second after assertion.
  • Cold load pickup generates false fault indications on re-energization unless a cold-load or inrush detection scheme is implemented in the relay.
  • Reclosing that takes longer than five minutes puts you outside FLISR's stated requirement.
  • Miscoordination detection disabled does not mean miscoordination is ignored — FLISR still analyzes it, and could re-energize the line if the miscoordinated section is considered available.
  • Unmapped PTs with voltage checks enabled are treated as a failed voltage check, and the device is skipped.
  • Editing a commissioned canvas decommissions it. Budget for re-commissioning whenever the model changes.
  • An unpublished model export is locked to you. Publish before sharing.
  • Upgrading FLISR disarms every commissioned feeder, and downgrading requires decommissioning first.
  • Return to Normal does not check phasing. Local devices must.
  • Out-of-service states that disagree with the as-built PSM state block Return to Normal entirely.
  • Duplicate assets between a substation and a distribution model make MDI alarm on every delta update until one copy is removed.
  • Time synchronization is a prerequisite, not a nicety — look-backs and measurement validity depend on accurate timestamps. See Time Synchronization.
