☰The rules, stated plainly

DMA

  • DMA automates what people used to do by hand: pulling oscillography, SOE, settings, properties, load profile, and power-quality data off devices, and rotating their passwords.
  • Everything starts in Resource Management. Define the resource and its connection first, then build the plan — a plan cannot use a resource that has no matching connection.
  • Schedule → plan → plan execution. The plan is the configuration; each scheduled run against each resource is an execution, and every execution is logged in DMA Diagnostics.
  • Listening beats polling where an RTAC is available: the RTAC notifies DMA on port 5000 that new data exists, and DMA pulls it over an encrypted database connection in one optimized transfer instead of iterating.
  • Storage is finite and self-grooming. DMA defaults to no more than 40 GB total and overwrites the oldest data as each data type approaches its limit — publish or use the API for anything that must be kept.
  • Credential rotation deserves its own discipline. Back up before every rotation, test communications first with a cheaper plan type, and keep plans under 250 devices.

1What DMA collects, and how the pieces fit

Device Management and Automation is a suite of Blueframe applications for automated data collection, management, normalization, and availability from critical infrastructure devices. It automates and accelerates collection of:

Oscillography & SOEEvent reports and sequence-of-events records — the Disturbance Monitoring package.
Settings & propertiesDevice settings, firmware versions, and property versions — the Configuration Monitoring package.
CredentialsAutomated password rotation and proxy-report collection — the Credential Management package.
Files & command resultsArbitrary files from a device file system, or the text output of an ASCII command — Custom Monitoring.
LDP & VSSILoad data profile and voltage sag, swell, and interruption records — Meter Monitoring.
And then moves itTo another Blueframe instance, an HTTPS or FTP endpoint, an email recipient group, or out through the REST API.

Every package pairs a configuration application (where you build plans) with an Archive application (where you view collected data and generate reports). Reports can be modified, refreshed, and exported to .csv for compliance or auditing.

Licensing is by feature and by resource count. Each plan-configuration application reports licence usage under its View menu. If no valid licence is detected, or the number of unique resources across configuration plans exceeds the licensed quantity, a banner appears showing both numbers until a valid licence is uploaded through System Settings. 2The core loop: resource, plan, execution

Both Initial Plan Execution options matter: On Save runs immediately on creation, Custom lets you set the first run time — useful for staggering a large rollout. (Animated in the browser.)

Building any plan — the common sequence

  1. Define the resource in Resource Management. Use the DMA Attributes Preset, which adds the specific parameters required for correct DMA operation and data storage.
  2. Add the connection(s) the data type requires. Multiple connection paths to one resource are normal, because some data is only reachable over a particular protocol.
  3. Launch the DMA configuration application and select New Plan.
  4. Define Name, Type, Initial Plan Execution, and Schedule.
  5. Select Resources — Ctrl+Click for non-consecutive, Shift+Click for consecutive, click again to deselect, and the search field to find by name. Move them to the right pane and confirm.
  6. Check the Connection column. If it reads No connections available, the resource has no connection matching the plan type — go back to Resource Management and add one.
  7. Create. DMA begins acting on the schedule.

3Polling versus listening

DMA Settings → General → Listening → Enabled, which disables all listening operations. The RTAC side is configured in ACSELERATOR RTAC (SEL-5033) to send notifications over port 5000. Reading the Listening Log The message column shows what the RTAC SEL Server sent: New Oscillography, New SOE, or New Settings. A Misconfigured message means the password is wrong, the IP address is wrong, or the device does not exist as a resource in Blueframe.

Listening applies to Disturbance Monitoring and Configuration Monitoring. Custom Monitoring and Meter Monitoring are scheduled-polling only. (Animated in the browser.)

4Disturbance Monitoring

Automated collection of oscillography and sequence-of-events data. Supports both scheduled polling and listening, and collected data can be published onward.

Advanced plan options

When Oscillography is in the plan Type, the settings cog beside the Type dropdown exposes:

  • Child-device record handling when there is no matching GUID.
  • A "Go Back To" date for oscillography collection.
  • File type selection, including advanced commands, when using an SEL ASCII connection. Which options a given device supports is in that device's instruction manual.
Collect the smallest useful record. Over a device's in-service life an automated system performs thousands of file and directory reads. SEL's guidance: configure Disturbance Monitoring plans to collect only CEV or COMTRADE records where possible, and where an SEL communications processor such as an RTAC is in the path, configure its event collection option to collect only CEV or COMTRADE. Higher-sample-rate reports can be pulled on demand during event analysis when detail is actually needed.

Supported devices

Native oscillography and SOE support spans the SEL fleet — the 251, 300G, 311 and 321 families, the 351 family including 351R/351RS/351S, 387 family, 400G, 401, 411L, 421, 451, 487B/487E/487V, 501, 551, 587, 651R, 700G, 710, 731, 734 family, 735, 751/751A, 787, 849, 851, the 2020/2030/2032 communications processors, and 2411/2414/2440 controllers — with per-device notes (for example the SEL-221S is EVE only, the SEL-251 family is SOE support only, and the SEL-300G is oscillography support only). Support for other SEL and vendor devices is handled through RTAC aggregation.

Third-party devices over MMS

  1. In Resource Management, configure and enable an MMS connection on the target resource.
  2. In Disturbance Monitoring, create an oscillography collection plan for it.
  3. After the plan executes, generate a report in Disturbance Monitoring Archive.

Supported COMTRADE formats over MMS are 1997, 1999, and 2013. SOE collection is not supported for third-party devices. Where a device has no MMS, use an SEL RTAC to collect the oscillography instead.

Disturbance Monitoring Archive

  1. Select New Report and add the resources of interest.
  2. Set the Time Period: Past 24 Hours, 1 Week, 1 Month, 6 Months, 1 Year, or Custom with start and end date and time.
  3. Select the Event Types — SOE, Oscillography, or both.
  4. Create. The populated report supports search, export, parameter modification, refresh, and record detail. From the Details view you can download an event record or launch the included event viewer.

5Configuration Monitoring

Automated collection of settings, firmware versions, and device property versions, for device-integrity analysis and compliance auditing. Supports polling and listening.

An RTAC needs two connections, because the two data types live in different places. Property data comes from the RTAC's Postgres database; settings data comes from the RTAC's API over HTTPS. Configure both connections on the resource, then build two plans — a properties plan whose Connection is the Postgres connection, and a settings plan whose Connection is the HTTPS connection. Getting one connection right and the other wrong produces a plan that silently collects only half of what you expected.

Setup, for the RTAC case

  1. In Resource Management, give the RTAC resource both a Postgres and an HTTPS connection. (Postgres: port 5432, Database 3530.)
  2. In Configuration Monitoring select New Plan; define Name, Type = properties, Initial Plan Execution, and Schedule.
  3. Select Resources, apply the selection, and confirm the Connection column shows the Postgres connection. Create.
  4. Repeat with a second plan, Type = settings, confirming the Connection column shows the HTTPS connection. Create.

Both plans then execute on their schedules, and Configuration Monitoring Archive shows the collected data.

Configuration Monitoring Archive

Generate a resource audit report: select resources, choose the time period (24 Hours through 1 Year, or Custom), and Create. The report supports search, export, parameter modification, refresh, and record detail — the artifact you produce when someone asks what changed on a device and when.

6Credential Management

Automated password rotation, credential checkout, password verification, and reporting. Where devices sit behind an SEL security gateway, DMA initiates rotation and collects and parses the generated passwords proxy report into a secure database for use across the platform.

Credential Management data lives in a separate database from other DMA data, and credential records have no storage lifetime — they are not groomed away. (Animated in the browser.)

Password complexity

  • Complexity is derived from the model type, and Credential Management suggests a maximum supported complexity and applies it by default when the firmware attribute is defined on the resource.
  • Because complexity varies with firmware version, the supported complexity for a particular device may differ from the model default. Options can be applied to a whole plan or to individual resources within a plan.
  • Hovering an option shows a tooltip with the password length and the character set used to generate the random password. Custom lets you choose both length and permitted characters.
  • Global exclusions live in Admin Settings → Global Defaults → Password Settings: choose characters excluded from all generated passwords. Validation keeps generation viable — at least one character must remain in each class, and hyphen and period cannot both be excluded.
When you override the default complexity, check the device's manual. Credential Management will happily generate a password the device will not accept.

Password exceptions

  • A temporary exception sets a known, easy-to-remember access-level password with a user-defined end date. When the date arrives, DMA automatically generates a new complex password, updates the device, and resumes the normal plan.
  • An exception with no end date stays until cleared — useful for keeping a known Level 1 credential for read-only local access.

Checkout — self-service temporary access

  1. Grant the Can Checkout advanced permission to the appropriate roles (Permissions → Credential Management, as an administrator).
  2. Set the defaults in Admin Settings → Global Defaults → Checkout Settings: default and maximum checkout duration, how many resources one checkout may include, whether completed-checkout history is retained, and the Default Passwords — which access levels are eligible and what password is used per complexity type.
  3. A user with Can Checkout selects the Checkout tab → Checkout Resources, enters a name and reason, selects resources, and optionally adjusts start and stop times.
  4. They define the checkout password — unless an administrator configured default passwords, in which case it cannot be overwritten.
  5. DMA sets the credentials; Status shows when they are set on the device or what is blocking it.

At the stop time, DMA automatically sets the credentials back to complex, unknown passwords. If a password change occurred during the checkout — manually or by schedule — new passwords are generated and applied; if not, DMA restores the last known password per credential type. Stop Checkout ends it early. Checkout actions are trackable in Credential Management Archive and in Blueframe's System Logs.

Users with Can Checkout cannot create or edit automated credential plans. The role is deliberately scoped to self-service access, not to rotation configuration.

Password verification

The SEL Devices – Password Verification plan type checks whether the credentials on the physical device match what Blueframe believes they are: it connects to the resources in the referenced plan and attempts to authenticate to the target accounts with the stored credentials, on a schedule. Results appear as a report in Credential Management Archive. This is the answer to "are we actually in sync?" — ask it regularly.

Pre-rotation off-box credential export

Planned passwords can be exported to an off-box SFTP server before a rotation executes, to cover the case where Blueframe becomes disabled mid-rotation.

  1. In Resource Management, add a resource for the SFTP server endpoint and configure an SFTP connection with credentials.
  2. In Credential Management, go to System → Admin Settings → SFTP Settings.
  3. Enable Off-Box SFTP and specify the resource, the resource connection, and the remote path for planned password reports.
  4. Run Test Connection — it transfers a non-sensitive test file and verifies write access.
When enabled, a successful export is a mandatory prerequisite to rotation. If the SFTP server is unreachable, authentication fails, or the report cannot be written to the remote path, rotation does not proceed — these are treated as blocking errors specifically to prevent partial or unrecoverable rotations. A security log entry is written on every successful export, and SFTP connection and transfer diagnostics live in Admin Settings.

Archive permissions and credential policies

  • Credential Management Archive can display sensitive information. From an account with Can Manage, open Permissions → Credential Management Archive and grant Can View Passwords only to the appropriate roles. Any user with it can generate a Current Password Report.
  • Credential policies (View → Credential Policies → New Policy) define common credential settings for a collection of resources, so reports can be generated against a policy rather than device by device.
  • System → Reports provides the Planned Passwords report, including reports exported to off-box storage.

SEL's implementation recommendations

Before you rotate anything

  • Prove the network first. On large deployments (more than 1,000 resources) or complex networks, use a cheaper DMA plan — Configuration Monitoring properties collection — to test communication reliability and identify which devices will rotate successfully.
  • Start with known, simple passwords in the rotation. Move to complex randomized automation only after sufficient testing.
  • Watch intermediary devices. Terminal services between DMA and the IED can drop or alter communications — flow control limits, MTU, or proxying — with negative side effects on how the password is actually set on the end device.
  • Decide which access levels need rotating, and how often. Always use unique passwords beyond manufacturer defaults, but not every credential level needs a schedule.

Backup and plan hygiene

  • Schedule outages and updates around rotations. Ensure all credential plans, including checkouts, are completed or resting before a system outage.
  • VM deployments: daily snapshots, monthly clones, records kept three to six months longer than the plan schedule; use replication, redundancy, and failover features.
  • Hardware deployments: use SEL BaRT before application or OS upgrades and before planned password changes.
  • Monthly: export the Archived Password report, the Current Planned Passwords report, and a Resource Management backup — all automatable through API calls.
  • Set System Logs retention to 365 days by default.
  • Plan sizing: under 250 devices per plan, limit schedule overlap, pause long-running plans until just before their rotation window, and understand plan-execution state before upgrading an application.
  • Consider redundancy — two Blueframe nodes, primary and backup.

7Custom Monitoring

Automated collection of arbitrary files or the result of a device command. Scheduled polling only.

Plan typeConfigureConstraint
File TransferA folder directory plus a regular expression identifying which files to collectOnly supported on file transfer protocols
Command resultAn ASCII command whose output is captured into a text fileDMA supports SEL ASCII commands and attempts non-SEL ones — SEL devices give consistent return prompts, non-SEL devices do not

Example: a NovaTech Orion

  1. In Resource Management, configure and enable the connection that reaches the device's file system. Blueframe supports SFTP and non-secured FTP to the Orion depending on its configuration.
  2. In Custom Monitoring, create a New Plan for file collection.
  3. Specify the remote file path and the file format, matching the structure and file types actually present on the device.
  4. After execution, open Custom Monitoring Archive and create a report containing the collected files.

In the Archive, pick a resource from the tree to see everything collected from it — searchable, filterable, and downloadable. When downloading, the dialog asks for a file name and you supply the extension.

8Meter Monitoring

Automated collection of load data profile (LDP) and voltage sag, swell, and interruption (VSSI) records. Scheduled polling only.

  • Supported devices: SEL-734, 734B, 734P, SEL-735, and the RTAC Trend Recorder (firmware R153). Other devices are handled through RTAC aggregation.
  • Advanced LDP option: limit the amount of data collected on the first poll. Disabled by default — meaning DMA gathers everything available on the device. The setting only takes effect on the first poll for a resource in a plan; where a resource is in multiple LDP plans, it applies on the first execution that includes it.
  • Setup: configure the supported SEL devices in Resource Management, then New Plan → name → Type and Schedule (the gear icon in the Type field sets the initial-collection limit) → Select Resources → Create.

Meter data is the storage hog. SEL's explicit guidance: ensure adequate disk space when configuring Meter Monitoring, and if meter recorders are set to a high level, limit the number of metering devices DMA collects from.

9Publishing collected data

DMA can publish Disturbance, Configuration, Custom, and Meter Monitoring data from one Blueframe instance to another — encrypted in transport, private database to private database — or to a web server, an FTP/SFTP/FTPS server, or an email recipient group.

On the receiving Blueframe node

  1. Create a user account with a role that has Can Launch permission to the DMA REST API. SEL recommends a specific user and role dedicated to publishing.
  2. Install the appropriate Archive application if the published data should be viewable there. Without it the data still arrives and is reachable through the DMA REST API — it just cannot be browsed.

On the publishing Blueframe node

  1. In Resource Management create a New Resource, and under Attributes → Preset select Blueframe.
  2. Open its Connection Settings. Protocol must be HTTPS, Port must be 443, Credential Type must be Basic, and the user and password must match the account created on the receiving node. No child resources are needed.
  3. Configure the publishing plan in the relevant DMA application.
Two ordering rules that are easy to get wrong. First: configure the publishing plan before the collection or listening plan, because DMA publishes newly collected data — anything gathered before the publishing plan existed will not be sent. Second: export the resources from the publishing node's Resource Management and import them into the receiving node's, so published data is associated with the correct device on arrival.

Email notifications use the Notifications recipient groups described on the platform page, which in turn require an SMTP server connection defined in Resource Management.

10DMA Tools — diagnostics, API, settings

DMA Diagnostics

Four workspaces:

WorkspaceUse for
Plan ExecutionsLive and Historical views. Live updates roughly every 5 seconds; a completed execution stays in the live table for 1 minute or until refresh, then appears in Historical. Filter by plan, execution start time, resource, and result — filtering by resource is the usual first move
PublishersLogging for configured publishing plans
Listening LogStatus and messages for listening operations — including the Misconfigured message described above

Detailed logging view: select an execution, then View under Details. It lists the high-level steps of the connection; selecting a step shows its logs in ascending time order, interspersed by time across log types to give a holistic view. Log types include Communications (standard ASCII transmit and receive, populated with the most recent information around an error), Executions (the request to execute a sequence and its inputs), and Service.

How much history you get is tied to the disk space allocated to Diagnostics data in DMA Settings, and to how frequently plans run against how many devices.

DMA REST API

  • Read-only programmatic access to the DMA private datastore, so collected data can reach tools outside Blueframe.
  • Launching the application tile displays Swagger documentation; the server should read /dma-rest/api/v1 - DMA.
  • Included with any DMA package purchase, but installed as its own package.

Retention uses two thresholds: once Begin Groom At is reached for a data type, DMA deletes the oldest data until Groom Down To is met. When adjusting Target Size, account for any non-DMA application data so you do not over-allocate the disk.

Reset Data clears all DMA collected data permanently and is unrecoverable, though it leaves the configured plans in place. Back up first, and stop active collection before resetting so deletion does not race with collection.

11Deployment architecture and sizing

Distributed Blueframe instances in substations or regional control centres. Best when data availability matters most and corporate-network communications may be intermittent. Local archiving means device data survives regardless of the WAN, with longer retention than the relay itself and better security around sensitive device information. Data is viewable locally or through a browser per instance.
Centralized One Blueframe instance reaching remote substation devices. Best when network communications are strong and reliable and substation aggregators such as SEL RTACs are in use — RTACs raise performance through listening, avoiding unnecessary connections. Where listening is not feasible, polling the RTAC as aggregator is still far more efficient than polling every device.
Mixture Both, chosen per substation. Common where some sites have reliable networks and others do not, and typical for systems modernizing existing architectures or with remote sites where improving communications is not feasible.

What actually drives performance: the size of collected reports, how often devices generate them, the number of endpoint resources per instance, how frequently DMA interacts with them, connection quality, and the volume of meter data. Setting a polling interval to an unnecessarily high frequency reduces DMA's ability to service the devices efficiently. And no amount of tuning compensates for unreliable communications paths — DMA operates in less-than-ideal networks, but collection reliability and responsiveness suffer significantly.

  • Backup file size is 1:1 with the size reported in the Total Used DMA Storage chart. Budget roughly 95 seconds per GB to back up and 65 seconds per GB to restore.
  • When restoring, ensure Resource Communication Services is installed and that the version at backup and the version at restore match.

12Gotchas

  • "No connections available" on a plan resource means the resource has no connection matching that plan's data type. It is a Resource Management problem, not a plan problem.
  • An RTAC configured with only one connection collects only properties or only settings, never both. Postgres for properties, HTTPS for settings.
  • The publishing plan must exist before the collection plan, or the first batch of data is never published.
  • Resources not imported on the receiving node means published data arrives unassociated with the right device.
  • Off-box export failure blocks rotation entirely. That is by design — but it means an unreachable SFTP server silently stops your password program until someone notices.
  • Checkout default passwords, once set by an administrator, cannot be overridden by the checkout user. Decide deliberately whether you want that.
  • Listening is on by default and disabling it in DMA Settings disables it for all applications, not just the one you were thinking about.
  • The first poll of a device is not the whole history. Twenty reports come first, then the rest across subsequent executions — do not conclude collection is broken after one run.
  • Meter Monitoring plus high-resolution recorders will fill the disk. Size the storage or limit the device count.
  • Licences are tied to the serial number or VM agreement. Replacing hardware means contacting SEL, not moving a file.
  • Uninstalling a DMA package deletes its configuration and stored data — export plans and back up data first.
