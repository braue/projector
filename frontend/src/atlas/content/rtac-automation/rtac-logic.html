IEC 61131-3 Logic on the RTAC

Programs, function blocks, and Structured Text on the RTAC logic engine — the task/scan model, SEL tag structures, timers and triggers, and the mistakes that load the default project

☰The rules, stated plainly

  • User logic runs in the IEC 61131 logic engine on a fixed task cycle: every cycle the protocol tasks, Tag Processor, and your POUs execute in the order set on the Main Controller tab. Nothing in logic updates faster than the cycle time.
  • Three POU kinds: Programs (standalone, keep their VARs), Function Blocks (instanced, stateful — timers, counters), Functions (stateless, same in → same out).
  • A function block only runs when its instance is called this scan. A TON inside an IF that stops being true stops timing.
  • SEL tags are structures: read .stVal/.instMag, check .q.validity, command with a rising edge on operSet.ctlVal.
  • An endless loop or over-tight cycle isn't a slowdown — the watchdog replaces your project with the default project and deasserts all contacts.

1Where your logic runs

The RTAC splits work between protocol engines (client/server drivers that move data in and out) and the logic engine (the IEC 61131-3 runtime that executes your code against the tag database). The 5033 manual gives you three places to put logic, in ascending order of power:

1 · Tag Processor expressionStructured Text in a Source Expression column — scale, combine, or gate values on their way to a Destination Tag. All assignments complete before data passes to the protocols.
→
2 · User Logic POUsPrograms, functions, function blocks, GVLs, and data types under the IEC 61131-3 ribbon — the real programming area.
→
3 · Device Controller CFCContinuous Function Chart against a device's controller PINs — for advanced per-device applications.
  • Languages: the RTAC supports only Structured Text (ST), Ladder Diagram (LD), and Continuous Function Chart (CFC) of the IEC 61131-3 set. This page focuses on ST; LD/CFC use the same operators and function blocks as boxes and pins.
  • Contrast with relay logic: this is a full programming environment with loops, structures, and libraries — not the fixed-form Boolean equations of SELogic on the relays (see SELogic Control Equations in atlas). Protection-speed decisions stay in the relay; the RTAC orchestrates.
  • If you write ST in the Tag Processor, review the generated code in the Code tab after saving and check for "invalid statement" warnings — SEL's own note.

2The task/scan model

Everything is periodic. The RTAC executes all tasks each task cycle time interval they are assigned to. Two configurable processing cycles exist: the main task (SCADA and slower work) and the automation task, which runs independently and faster — as fast as 1 ms. By default every task runs in the main cycle; you move tasks to the automation cycle from the Main Controller tab (Move To).

One task cycle: collect → execute in configured order → publish. Below: cycle times that divide evenly into one second start at the top of the second; an overrun (red) is absorbed by later cycles, not dropped. ▶ Animated in the HTML edition.

  • Alignment: cycle times evenly divisible into 1 s execute at the top of each second of system time (100 ms → first cycle at the top of the second, then every 100 ms). Non-divisible times still lock to system time, just not to the second boundary.
  • Sizing: online, the Tags view shows per-task and overall task timers in µs. SEL's rule: main cycle time ≥ 140% of the overall task timer, leaving headroom for web/HMI access. A 20 ms cycle with 50 ms of work doesn't drop tasks — it borrows subsequent cycles and degrades web performance.
  • Controls are edge-sampled per cycle. A control high→low→high inside one cycle stores only the last value — the edge is missed. SEL's rule: don't execute control operations faster than half the cycle interval.
  • Main and automation tasks are isolated. They run at different priorities (automation is higher and can interrupt main), so referencing a tag owned by the other task's GVLs or devices is a compilation error — it prevents the race where automation rewrites values mid-read. To pass data across, use the CrossTaskData library (fb_CrossTaskWrite/fb_CrossTaskRead: one writer per mutex ID, mutex-protected copies via ADR()/SIZEOF()). Automation task timers live at SEL_RTAC.Application.Automation_SystemTotal_task_timer in a watch window.
The watchdog is the enforcement. The RTE Performance Watchdog (time-out set on the Main Controller tab) monitors task run time. If a task monopolizes the CPU — an endless WHILE, for instance — the RTAC loads the default project in place of yours, logs the RTEWatchdog expiration, lights ALARM, and deasserts all contacts. The RTE Exception Watchdog does the same for NULL-pointer-style faults.

3POU types: Program, Function Block, Function

POUStateUse it forRules that matter
ProgramVARs retained while runningTop-level logic; the only POU that can stand alone — you can't use the others without oneUnique name; acts directly on globals; one program's VARs invisible to another
Function BlockPer-instance, retained between callsTimers, counters, anything with memory — declare instances in VAR, one per useRuns only when referenced: myTon(IN := x, PT := T#3S); then read myTon.Q
FunctionNone (VARs lost on return; VAR_STAT is the exception)Repetitive stateless math — same inputs always return the same output (think SQRT())Call by assignment y := Fn(a, b); or with outputs Fn(a, out1 => loc1);
Function blocks must be called every scan to keep running. SEL's own example: if a program guards my_ton(IN := b, PT := T#3S); inside IF a THEN … a := FALSE; END_IF, the TON starts timing on the first scan and then never executes again — it never reaches PT. Call the instance unconditionally; gate its IN instead.

Variable classes: VAR (local), VAR_INPUT, VAR_OUTPUT, VAR_IN_OUT (by reference — can't be a constant, can't be read through the instance), VAR_TEMP (reinitialized every call), VAR_STAT (static, survives calls), VAR CONSTANT, VAR_GLOBAL in GVLs (reference globals with the leading-dot scope operator .iGlobVar1 when a local shadows them), and VAR_GLOBAL RETAIN (§9).

4Structured Text essentials

(* declaration part of the POU *)
VAR
   n      : INT := 12;      (* init optional; default 0 *)
   ratio  : REAL;
   almTmr : TON;            (* FB instance *)
   msg    : STRING(35) := 'hello';
END_VAR

// body — both comment styles appear in SEL examples
ratio := INT_TO_REAL(n) / 100.0;   (* no implicit narrowing;
                                      convert explicitly *)

IF temp < 17.0 THEN
   heating_on := TRUE;
ELSIF temp > 25.0 THEN
   heating_on := FALSE;
ELSE
   (* hold state *)
END_IF;
CASE mode OF
   1, 5   : BOOL1 := TRUE;      (* value lists *)
   10..20 : BOOL3 := TRUE;      (* ranges *)
ELSE
   BOOL1 := NOT BOOL1;
END_CASE;

FOR i := 1 TO 100 BY 2 DO
   IF arr[i] = 70 THEN j := i; EXIT; END_IF;
END_FOR;

WHILE counter <> 0 DO       (* REPEAT…UNTIL also exists;
   var1 := var1 * 2;            CONTINUE skips ahead.
   counter := counter - 1;      Endless loops starve the CPU
                                and trip the watchdog. *)
END_WHILE;

IF abort THEN RETURN; END_IF;  (* leave the POU *)
  • Operators, high to low: ( ) · function call · EXPT · negation - · NOT · * / MOD · + - · < > <= >= · = <> · AND/& · XOR · OR. Parenthesize anyway: (4+2)*6 ≠ 4+(2*6).
  • Identifiers: not case-sensitive (Var1 = var1); no spaces/specials; no repeated underscores; unlimited length; single-character S and R are reserved. Same name in two programs is fine — the namespace differs; GVL names qualify collisions (gvl1.myVar).
  • FOR trap (documented): if the end value equals the counter type's limit (SINT counter to 127), the loop never terminates.

SEL data classes wrap every protocol/system tag in an IEC 61850-shaped structure — value plus quality plus time:

ClassShape

Timestamps (.t) carry clock-sync flags and a source (IRIG_B, NTP, DNP, PTP…). Full structure detail: the tags & quality page in atlas.

6The function blocks you actually use

FBBehavior (per the 5033 reference)
TONTurn-on delay: rising IN starts ET counting (ms) toward PT; Q TRUE once ET = PT and IN still TRUE. IN FALSE → Q FALSE, ET := 0.
TOFTurn-off delay: IN TRUE → Q TRUE immediately; on falling IN, ET counts to PT, then Q drops.
TPPulse: rising IN → Q TRUE for exactly PT, regardless of IN dropping early.
R_TRIG / F_TRIGRising/falling edge detect: Q TRUE for one processing interval on the edge, then FALSE even if CLK holds.
CTU / CTD / CTUDCounters (WORD): CTU counts rising CU edges up to PV (Q at CV ≥ PV; RESET zeroes); CTD counts down from PV to 0 (LOAD reloads); CTUD does both.
SRSet-dominant latch: Q1 = (NOT RESET AND Q1) OR SET1 — SET wins if both high.
RSReset-dominant latch: Q1 = NOT RESET1 AND (Q1 OR SET) — RESET wins if both high.
SEL extrasTEX (expiration timer — Q one cycle when ET = PT), TI/TIV (self-restarting interval timer, TIV validates PT range), TPUDO (pickup + dropout delays in one block), PulseDecoder (executes a pulseConfig on any BOOL), RTC.

R_TRIG + TON on one input. The edge gives one scan of Q; the TON needs IN held for the full PT — the second, short assert never produces an output. IN dropping resets ET to 0. ▶ Animated in the HTML edition.

7Tags in logic: read, check, write

  • Naming: Device.Point.attribute, autocompleted as you type — Relay_1_DNP.AI_0000.instMag (client device → first analog input → instantaneous value). Everything from protocol clients/servers, virtual tag lists, and GVLs is global to user logic.
  • Check quality before acting. SEL's own Tag Processor example gates a mapping on Line_1_DNP.AI_0000.q.validity = GOOD and falls back to the backup relay's tag otherwise. In POUs, compare against the enumeration (x.q.validity = validity_t.good) or run ValidityCheck(tq := x.q); — it forces validity to invalid on overflow/badReference/failure and questionable on oldData/outOfRange/oscillatory/inconsistent/inaccurate.
  • Write controls with edges. Control classes expose oper structures; a rising edge on operSet.ctlVal issues the operation, and the value must return low before it can trigger again — writing TRUE a second time does nothing (SEL's Mirrored Bits example: SEL_351R_1_MB.TMB_1.operSet := TRUE sets status once; only operClear after it changes anything). Physical contact outputs follow the same operSet/operClear/status pattern. Verb-level detail (pulseConfig, DNP verbs): RTAC Quick Facts and the DNP pages in atlas.
  • Deadbanded vs raw: MV gives you .instMag (every scan) and .mag (deadbanded); pick deliberately.

8Patterns

(* Edge-detect a SCADA command — act exactly once.
   DNPC verbs: operClose/operTrip/operLatch…/operPulse *)
trigClose(CLK := SCADA_DNP.BO_0000.operClose.ctlVal);
IF trigClose.Q AND permissive THEN
   Relay_SEL.RB01.operSet.ctlVal := TRUE;  (* SRBC *)
ELSE
   Relay_SEL.RB01.operSet.ctlVal := FALSE;
END_IF;
(* the FALSE write re-arms the downstream edge *)
(* Seal-in / latch: SR is set-dominant *)
sealed(SET1 := startCmd, RESET := stopCmd OR tripOK);
Run_Status.stVal := sealed.Q1;
(* Q1 = (NOT RESET AND Q1) OR SET1 *)
(* Time-delayed alarm, quality-gated: 5 s of proof *)
vGood  := Bus_DNP.AI_0003.q.validity = validity_t.good;
almTmr(IN := vGood AND
             (Bus_DNP.AI_0003.instMag > HiLimit),
       PT := T#5S);          (* call every scan! *)
Volt_High.stVal := almTmr.Q;
(* Toggle a test value once per second (1 s cycle) —
   heartbeat for mapping checks *)
TestBit.stVal := NOT TestBit.stVal;
(* flips once per task cycle; at 100 ms it's 5 Hz.
   Online, Watch/Force in Online Debug does the same
   without code *)

9Gotchas & fine print

  • Retained variables: VAR_GLOBAL RETAIN survives power cycles, reboots, and project sends — but initializers in the declaration are ignored (existing memory wins); initialize in a program if you need a value. Memory budget is 28.5 KB (check consumption with SIZEOF()). The list order is the identity: append new variables at the end, keep one retained list per project, and if you must reorder, check Re-initialize Retain Variables on the send.
  • Downloads: Send Complete Project updates all settings and restarts the RTAC (non-retained state resets). Send only custom IEC 61131 logic skips the reset for quick iteration — but sends no other settings, so always finish with a complete-project send to put the unit in service and keep the readable-back copy current.
  • Task starvation is real: the automation task preempts main. Endless/tight loops, array overruns, and bad pointers can trip the watchdogs — and RTE Performance/Exception/OOM watchdog expiry replaces your project with the default project and deasserts every contact. Log Application_Status in the Tag Processor to catch restarting tasks.
  • Unused GVLs get optimized out at compile — you can't watch or force their variables online. Reference them somewhere if you need them live.
  • Memory layout isn't yours: never assume tag lists are contiguous or ordered in memory; renaming variables can move them. Use arrays/structures when layout matters; pragmas like {attribute 'subsequent'} are suggestions, not guarantees.
  • Angles: CMV angles are degrees; the built-in trig is radians — deg_to_rad()/rad_to_deg().
  • Debugging: Online Debug gives watch/force of any tag; the Output window lists compile errors — double-click to jump to the line.
