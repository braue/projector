Substation computing

  • A substation computer is a computer built for the environment, not a rack PC in a nicer case: no fans, no rotating drives, no vent holes, wide temperature range, and dual power supplies.
  • The SEL-3350 is one platform with several personalities. It can run as an RTAC, as a Blueframe application platform, or as a Windows or Linux machine.
  • Blueframe is a container-based application platform on a hardened Linux base, accessed through a secure web environment — not an operating system you administer directly.
  • Blueframe's central idea is shared data: IEDs, connections, and users are entered once, and each application subscribes to what it needs.
  • Use a computer where you need applications; use an RTAC where you need deterministic control. They are different tools that happen to share hardware.
  • A general-purpose OS in a substation brings general-purpose obligations — patching, antivirus, account management, backups.

2What Blueframe is

Blueframe is an embedded, modular, container-based application platform designed to operate in a secured environment. You choose which solution applications to install; management tools for common system configuration come included.

The security posture is part of the design: a hardened Linux base with measures such as allowlisting, application containerization above it, and web-based access rather than a desktop. (Animated in the browser.)

What the layers mean in practice

  • Containerized applications mean each app is packaged with its dependencies and isolated from the others. Installing or removing one does not disturb the rest.
  • Modular selection means you install only what you need — a single application, or a suite designed around a particular industrial problem.
  • Shared data is the operational payoff. Devices, connections, and user accounts are configured once at the platform level rather than repeated in every tool.
  • Web-based access means no client software to distribute and one place to enforce authentication.
  • Pre-installed OS. Blueframe hardware ships with the Blueframe operating system already installed; initialization is a setup workflow, not an OS build.
  • Virtual deployment is available for enterprise implementations, with resource requirements depending entirely on the applications being run, under a subscription contract with SEL.

Do not put control logic on a general-purpose operating system. A Windows update, an antivirus scan, or a background process can stall a task for seconds. That is entirely acceptable for an application and entirely unacceptable for anything operating a breaker. If the function must happen on a schedule, it belongs in the RTAC or in the relay — see the timescale discussion in Substation Automation, End to End.

5Operational obligations

A computer in a substation carries responsibilities an embedded controller does not. Plan for them at design time, because they will be audited.

  • Patching. Windows and Linux need a documented patch process with an outage window. Blueframe's hardened, containerized base narrows the surface but does not remove the obligation.
  • Accounts and authentication. Integrate with the central directory where policy allows, and eliminate shared local accounts — the same principles as RTAC Users & Security.
  • Backups. Configuration, applications, and collected data. Prove the restore, not just the backup.
  • Logging. Ship security and application logs to the central collector rather than leaving them on the box.
  • Time. Discipline the clock from the station source; collected records with a wrong timestamp are worth very little.
  • Change control. Installed applications and their versions are part of the station's configuration record.
  • Physical and network placement. Decide which network segment it belongs to and what it is allowed to reach, in both directions.

6Gotchas

  • Treating it as “just a PC.” It sits inside the electronic security perimeter and inherits every obligation that implies.
  • Sizing from today's application list. Storage and memory needs grow as more applications are added; for virtual deployments the requirements depend entirely on what is running.
  • Choosing the personality late. Whether an SEL-3350 will be an RTAC or a Blueframe platform affects licensing, configuration, and the skills needed to support it. Decide during design.
  • Local HMI without local authentication. A touchscreen in the control house with control capability and no login is an open control point.
  • Automatic event collection filling the disk. Retention and archiving policy, set on day one.
  • No plan for the box's own failure. Ask what stops working when it does — and confirm that protection and SCADA are not on that list.
  • Duplicating device data by hand in applications that could have subscribed to the shared data. That is precisely the copy-error problem the platform was designed to remove.
