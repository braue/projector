The SEL-2240 family — modular substation I/O on a deterministic EtherCAT backplane, with an RTAC as the single CPU for up to 60 modules across distributed nodes

☰The rules, stated plainly

  • An Axion node = chassis/backplane (SEL-2242) + at least one SEL-2243 Power Coupler + I/O modules. Exactly one RTAC per EtherCAT network (integrated SEL-2241/-2241-2 module or an external SEL-3350/3555), controlling as many as 60 modules across six nodes.
  • The internode bus is EtherCAT — a real-time Ethernet fieldbus where one telegram carries every module's data and each device reads/writes it on the fly. No switches, ever, on EtherCAT ports.
  • Modules install contiguously from Slot A, no gaps; the Node Connections Editor listing must match physical placement or the network won't initialize.
  • Default failure posture: 25 ms of message errors → the whole network shuts down and all outputs de-energize (Disable_On_Network_Error = TRUE).
  • Every input gets a 1 ms SER time stamp; AC modules across the system sample synchronously against a common reference.

1What an Axion is

The SEL-2240 Axion is SEL's modular I/O and control platform: it pairs the RTAC's protocol engine, security, and IEC 61131 logic with a suite of rugged I/O modules, connected over a deterministic Ethernet network. A node is a 10-slot, 4-slot, or dual 4-slot chassis holding an optional integrated RTAC module, one or more power couplers, and up to nine I/O modules in any mix — the node doesn't need to be full. Scale past one chassis by linking nodes over EtherCAT, which the manual describes as creating a "virtual Ethernet backplane" between I/O nodes with no loss of speed or determinism; a single CPU serves the whole network. Fiber between nodes buys electrical isolation and distance.

Typical roles (per the IM's applications section): distributed I/O in the yard with fiber back to the control house instead of high-energy copper runs, RTU replacement, bay control with the optional 7-inch touchscreen (10-slot, RTAC module in Slot A required), synchronized metering for load-shed / microgrid / sync-check schemes, and DFR-style recording.

2EtherCAT: how the bus stays deterministic

EtherCAT (a Beckhoff-originated open standard) fixes the two problems that make plain Ethernet a poor fieldbus — nondeterminism and per-device frame overhead. The trick: one telegram carries I/O for many devices, under a dedicated EtherType. Each module's FPGA/ASIC is configured at network initialization (the FMMU process) to know exactly which bytes of the telegram are "its" region — and the RTAC keeps the system deterministic by starting every telegram on a fixed schedule.

One RTAC, one telegram, every module. The frame streams out through the node chain, each module writes its channel states into its assigned region on the fly, and the completed telegram lands back in the RTAC tag database. ▶ Animated in the HTML edition.

  • Topologies: daisy-chain (sequential), star, or a combination — couplers create the links. Star topologies still ride the same sequential telegram; a star just gives each branch its own slot on the "message train." Hard rule: only one path between the first node and any remote node (no rings).
  • Port roles: the coupler's PORT 1 in Slot A is the node's incoming (IN) port; every other coupler port is outgoing (OUT). PORT 2 never operates as an IN port. Connect OUT of one node to IN of the next.
  • Media & distance: coupler EtherCAT ports are 10/100BASE-T copper or 100BASE-FX fiber (LC). Copper EtherCAT cables must be < 3 m (use double-shielded CAT5E/CAT6; SEL-C627F). Fiber: multimode ≈ 2 km, single-mode ≈ 15 km approximate range.
Never connect an EtherCAT port to an Ethernet switch, media converter, or any other Ethernet device. Coupler ports connect only to other couplers of the same type or to an RTAC's EtherCAT port — anything else can stop or destabilize the whole network (IM caution).

5Configuring Axion in ACSELERATOR RTAC

  • Insert modules: Insert ribbon → SEL Axion → pick Power Coupler / Digital / Analog type. The only Connection Type is Client-Ethernet (the module is an EtherCAT server). Names get an _ECAT suffix, and the module name becomes the prefix of every tag it owns — so name modules by node + slot (Node_2_Slot_C_ECAT) and tags locate themselves.
  • Node Connections Editor (click EtherCAT I/O Network in the project tree): attach modules to nodes so the listing exactly matches physical slot placement — the network cannot autoconfigure otherwise. Add nodes with +, define the internode cabling (which OUT port feeds which node's IN port). The editor only accepts valid topologies. SEL recommends adding and verifying one node at a time.
  • EtherCAT Discovery: or do it backwards — cable everything, go online, run Discovery, and Import the found topology. Import overwrites existing EtherCAT/module settings with defaults, so save a project copy first. On R153+ firmware, unused ports/empty slots are disabled once settings load — force the EN POU pin FALSE to re-enable discovery of new hardware.
  • External RTAC: SEL-3530/-3530-4/-3350/-3555 must first dedicate an Ethernet port to EtherCAT via the web UI (Ethernet Network → Enable EtherCAT). One port only, all other services drop off it, it can't be the gateway port, and bonding/DHCP/PRP are unavailable; don't assign 128.0.0.0 anywhere. SEL-3555/3560E use PCI expansion-card ports. Integrated 2241/2241-2 modules skip all this — the backplane port is factory-fixed EtherCAT.
  • Health at a glance: the network's POU pins expose Client_State (5 = operational; 11–14 = error, incl. 13 = burden > 70 %, 14 = processing interval exceeded), message counters, Servers_Attached_Count, execution times (Client_Max_us), and Time_Synchronization — network time-sync quality in ns.

6How module points appear as tags

Each module carries a fixed tag set, updated by the network automatically and evaluated by the logic engine at the task rate (100 ms default). Two diagnostics ride on every module: STATUS (Operational / Non-Operational) and ERROR (No Error / Cable Error — the wiring no longer matches settings). Disable unneeded tags — on AC/LEA modules only enabled tags occupy the EtherCAT frame, and an over-full frame throws "EtherCAT Bandwidth Exceeded."

Digital inputs — three tags per point

  • INPUT_xxx — debounced state for logic; last recorded state at the task rate.
  • INPUT_SOE_xxx — state + time stamp buffered every 1 ms by the EtherCAT network, independent of the logic interval (4 ms–1 s). Log this for high-speed SER.
  • INPUT_EDGE_xxx — time of first assertion, before debounce qualifies. (SOE/EDGE disabled by default on R118+; unavailable in ac mode.)
  • DC mode: user-set pickup/dropout debounce (default 10 ms). AC mode: fixed 2 ms pickup / 16 ms dropout — and it's processor-hungry: ≤ 2 nodes of ac inputs, keep Client_Max_us under ~500 µs.

Outputs and analogs

  • DO points are IOC tags: operSet / operClear / status, plus operPulse with OnDur/offDur/numPls — native pulse trains, mappable straight from a DNP TRIP/CLOSE via the Tag Processor. Pulses execute in multiples of the RTE cycle.
  • dc AI points are MV tags (INPUT_VALUE_xxx) with engineering-unit scaling (EU high/low vs. physical high/low — e.g. 4–20 mA ⇒ −50…150 °C), high/low warn + alarm setpoints with deadband, rate-of-change alarm, and filter A/B/C selection.
  • AC/LEA measurements are Simple Tags: CMV vectors (vector_t mag∠ang) and MV reals; timestamp/quality attach automatically when mapped in the Tag Processor.

7The AC metering module (SEL-2245-4), in depth

Four CTs (1 A or 5 A nominal, no setting needed — 0.05–22 A continuous, 22–100 A symmetrical for 25 s, 500 A 1 s withstand) and four PTs (300 V nominal, 5–400 V L-N measuring, 600 V for 10 s), delta or wye, ABC/ACB. Settings: CT ratio 1–50,000, PT ratio 1–10,000, per-tag enables for three streams:

  • RMS (kV units, 5 Hz update) and fundamental (V units, 200 Hz update) magnitudes/angles, sequence components I0/I1/I2/V0/V1/V2 (±0.2 %), per-phase and 3-phase P/Q/S/PF (±0.1 % typ.), frequency ±0.005 Hz.
  • Synchrophasors: IEEE C37.118.1-2011 (+a-2014) Level 1, software-selectable P or M class; VA/VB/VC/VS, IA/IB/IC/IN, V1/I1, f and df/dt at 120 Hz processing; message rates to 60 (or 120 on 2245-4/-42/-411 with a 2241-2/3350/3555/3560 CPU).
  • Waveform recording: triggered COMTRADE at 1/2/4/8/24 kHz, records 6 s @ 24 kHz up to 144 s @ 1 kHz, edge-triggered by the module's Event_Trigger Boolean, two back-to-back events, stored locally then fetched via the RTAC web Event Collection page. Pad pre-trigger by ≥ 2 task cycles — the trigger travels over EtherCAT.

Because all AC modules in an Axion sample against a common reference, multi-module measurements are inherently phase-comparable — the basis for sync-check, load-shed, and microgrid schemes without post-alignment. For protection-grade work the 2245-42 adds 40–90 Hz tracking, 250 Hz updates, harmonics to the 63rd, frequency groups, Recording Groups (combined COMTRADE with 2244 digitals, up to 6 groups), and the Axion Wave Server — 3 kHz point-on-wave streaming over C37.118 (3,000 msg/s, 96 channels, needs a 2241-2/3350/3555/3560). A full DFR build scales to 192 analog channels (2245-42/-43 modules; SEL-3555 required above 96) and 1,728 digital channels, storing up to 1,024 COMTRADE records and 500,000 1 ms SOE entries — sized to exceed NERC PRC-002/PRC-028 (system DS).

8LEA inputs: metering without the PT

LEA = low-energy analog — millivolt-to-tens-of-volts signals from low-energy sensors instead of 300 V-class instrument transformers. The 2245-221 (4 LEA) and the LEA half of the 2245-411 measure 0.05–22 Vac rms (VNOM 1.5 V, 30 V peak, 300 V 10 s surge) at ±0.1 % typical above 50 mV, with per-channel magnitude (0.5–1.5×) and angle (±10°) compensation settings to calibrate the sensor string. The IM's application list is blunt about the point: connect external split-core CTs and eliminate outage costs — clamp on, don't break the circuit. The -431/-432 variants extend the family with 0.033–10 Vac LEA voltage inputs. LEA modules carry the same Simple-Tag streams, oscillography, and (on the -411, -431, and -432) synchrophasor support as the CT/PT module.

9Timing & determinism, as documented

  • Network scan: telegrams start on a fixed schedule; the EtherCAT network updates — and buffers DI SOE state — every millisecond. All inputs get 1 ms SER time stamps.
  • Logic: IEC 61131 tasks run 4 ms–1 s (two task classes; high-speed automation "as fast as one millisecond" per the IM); tasks evenly divisible into 1 s align to the top of the second.
  • Time sources: IRIG-B in/out on the RTAC module (demodulated accuracy 500 ns on the 2241), NTP/SNTP (±1 ms) and PTP; the 2241-2 data sheet claims sub-microsecond sync via IRIG-B or PTP for PMU work. The Time_Synchronization POU pin reports whole-network sync quality in nanoseconds.
  • Budget discipline: Client_State 13 fires at > 70 % network burden, 14 when the processing interval is exceeded — the documented fix is fewer enabled tags, fewer ac-debounce inputs, or splitting I/O across multiple RTACs.

10Failure, diagnostics & field practice

The fault loop: module drops off the network → its ENABLED LED goes dark and ALARM lights, the module's STATUS tag flips to Non-Operational — and, at the default setting, the whole network halts with outputs de-energized. Commissioning the replacement brings it back automatically. ▶ Animated in the HTML edition.

LEDs, everywhere the same

  • ENABLED (green): module operating normally on the network. ALARM (red): network initializing, or trouble.
  • Coupler adds POWER (green = supply healthy); 2244 modules add a red LED per I/O point (lit when asserted); RTAC modules add programmable bicolor LEDs and the Form C alarm contact.
  • LAMP TEST button on each coupler lights every LED in the node.

Choose your failure posture

  • Disable_On_Network_Error defaults TRUE: 25 ms of message errors kills all EtherCAT traffic and de-asserts every output — fail-safe, but one dead module downs the network. Set FALSE to keep the surviving modules running.

Swapping modules

  • Planned change: go online → Connections tab → Decommission the module first (clears its network settings so it's a clean spare; skipping this poisons the next system it lands in). Never decommission while network errors exist.
  • Failed module, network down: swap hardware, then force the EN pin FALSE and unforce (F6 / Shift+F6) to restart EtherCAT.
  • Failed module, network up: install, right-click → Commission, then cycle the module — tip it out until its LEDs extinguish, press back in. It joins automatically.
  • I/O terminal strips unplug (retaining screws) so wiring stays put. Couplers: de-energize first; a single-coupler node dies with its coupler. SFPs are the only hot-swap-rated connector; changing them live can drop the EtherCAT network.

Wiring quick facts: no bare conductors — ferrule or spade terminals. Coupler power: 14 AWG (15 A breaker) or 12 AWG (20 A); ground GND(3) and the backplane lug with ≤ 2 m of 14 AWG. DI/DO: 24–12 AWG (2244-2/DO), 28–16 AWG (2244-4, 2245-2). Fuse contact inputs ≤ 8 A. On the 2245-2, tie all input returns (even unused) together for command/control use. Coupler primary fuses are field-replaceable.
