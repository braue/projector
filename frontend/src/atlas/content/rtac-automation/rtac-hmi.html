Web HMI & Diagram Builder

The RTAC in a browser — the zero-config web interface, Diagram Builder screens bound to project tags, operator controls with confirm dialogs, and Axion bay screens

SEL-5035HPRJ / .binzrequest groupsHMI Remote Writeread-only modeSEL-5036AG2024-06

☰The rules, stated plainly

  • Every RTAC ships a web interface for free — reports, live data, diagnostics — over HTTPS. The graphical HMI is an ordered option built in ACSELERATOR Diagram Builder (SEL-5035) and loaded onto the RTAC.
  • An HMI screen is just controls bound to RTAC tags. The browser polls the RTAC in request groups: event polls fetch only changed tags, integrity polls refresh everything.
  • Controls are gated twice: the HMI Local/Remote Write permission on the user's role, and per-diagram role-based security configured in Diagram Builder. By default a confirm dialog appears before and after every control.
  • The HMI runtime (.binz) version must match the Diagram Builder project version — and clear the browser cache after a runtime upload, or screens render inconsistently.

1The built-in web interface — what you get with zero config

Browse to https://<RTAC-IP>. Defaults: Eth-1 on an SEL-3555/3560/3350 is 192.168.1.2; a USB-B connection to an SEL-3530/3505/2241 answers at 172.29.131.1. You must type https:// yourself unless Enable HTTP Redirect (port 80 → 443 forwarding, disabled by default) is turned on. On first connect there are no accounts — the RTAC prompts you to create the first administrator with a complex password (8–72 chars, upper + lower + number + special). Forget it and you're opening the case for the bypass jumpers.

Tags come in two flavors: device tags (from device connections in the RTAC project) and virtual tags. Diagram Builder has no scripting engine — do math in RTAC logic, land the result in a virtual tag, display that. CSV import is two columns (Tag Type, Tag Name) and overwrites all existing tags — export, append, re-import to add.

Diagram types: ordinary Diagrams (only these can be the project default), Popup Diagrams (created on demand at runtime, auto-deleted on close), and Synthetic Diagrams (templates driven by the Substitution Control's tag/property substitution — one template, many bays).

4Data binding — how a tag change reaches the screen

Every control and status belongs to a request group. Two timers per group drive updates: the Event Poll Interval fetches only tags that changed since the last poll; the Integrity Poll Interval refreshes every tag in the group. Put fast-moving metering in a quick group and static nameplate data in a slow one. A group that grows past 250 tags silently spawns an overflow group polling at the default interval.

The binding loop: tag change → event poll → widget update. The frozen frame shows the closed state and the poll path. ▶ Animated in the HTML edition.

  • Quality rides along. A bad-quality tag paints its control with a quality indicator (exclamation point on analog displays, yellow circle elsewhere); annunciator tiles inherit bad quality from any child.
  • Broken bindings are visible. HMI Debug Mode (gear icon → enable → relaunch) flags controls whose tag was removed or whose type no longer matches the RTAC project. The in-editor HMI Preview always runs with Debug Mode on and can optionally pull live data from an RTAC.
  • Tag hygiene matters: File > Remove Unused Tags shrinks the project and its browser load time; only tags in the project are available for dynamic trending.

5Operator controls — select, confirm, and who's allowed

By default the HMI shows a warning dialog before a control command is sent and a confirmation after the RTAC acknowledges it (Project Settings > Control Behavior; can be relaxed globally or per control). Breaker, Disconnect Switch, and Multifunction controls can also carry a Control Window — a docked or floating popup (opened by Ctrl+click or double-click, with its own timeout) listing the bound analog/binary I/O with custom button text; at least one binary output must be assigned or it won't appear. The Hide Logical Command Column property decides whether operators see the raw operation names (trip, close, pulse…).

What can lock a control

  • Role permission. Issuing controls requires the HMI Remote Write permission (remote browser) or HMI Local Write (local display) — held by Administrator, Engineer, and HMI Operator accounts by default. Roles and the permission model live on the security page in atlas.
  • Read-only mode. With Enable HMI Read-Only Mode set on the RTAC Dashboard, a timed-out session keeps showing data but every control locks; operating one prompts a login. (Activating read-only from the HMI without the RTAC-side flag just logs you out.) Conversely: Web Session Time-out = 0 keeps the HMI open and users can send controls and ack alarms without re-authenticating.
  • Always Authenticate = True on a control forces a credential prompt on every operation; Locked on Operator Blocked locks the control while its control tag has bad quality (an authenticated user can override).
  • Per-diagram roles. With role-based security enabled, the runtime Project Outline splits into Available and Disabled diagrams per user. Role names typed in Diagram Builder must match the RTAC's role names exactly — Diagram Builder has no awareness of the RTAC's role list or hierarchy, and you maintain the inheritance by hand. Requires HTML5 rendering (firmware R141+).

6Trends, SOE, and alarms in the runtime

Trending

  • Static trends: built in Diagram Builder (Trend Groups → Trend control → up to 4 tags); visible to all clients, unconfigurable at runtime.
  • Dynamic trends: created live (Trending > Create Trend), tags picked from the project, per-series colors, panning and point indicators.
  • Tooltip trends: double-click a metering label with Enable Tooltip Trending = True; up to 10 at once, minimizable to the diagram base.
  • Default trend settings (legend, gradients, axes, 12/24-h time) are set from the HMI; time-format changes need an HMI reload to apply.

SOE & Alarms viewers

  • Both viewers show at most 200 records — the full archive lives in the web interface reports / Alarm Summary. Timestamps are UTC by default, no DST; a manual offset applies to both viewers and only persists if you log out of the web interface.
  • Ack/delete single, selected, or all records; CSV export; saveable .fltrs filters; preconfigured filters for the four alarm states (Active/Inactive × Ack/Unack); per-severity alarm sounds keyed to the tag processor's Logging Priority.
  • Acking in the HMI acks the RTAC Alarm Summary too — one alarm state, two views. Auto-polling of the Alarms Viewer is off by default (you reload manually).
  • Alarm history view (runtime 3.11.0.231+, firmware R155+): a per-alarm chronology of alarm, return-to-normal, and ack events; buffer depth set by Max Alarm History Events Per Tag (10–100).
  • Acknowledgeable annunciator tiles have four states; from R155/R201, Reacknowledge on Alarm Normalization (Dashboard) decides whether a cleared alarm must be re-acked before it drops off.

7Bay screens — the Axion touchscreen flavor

Local touchscreens on bay control units use a different tool: ACSELERATOR Bay Screen Builder (SEL-5036), auto-installed with the settings software for touchscreen-equipped SEL devices. Insert an SEL Touchscreen device in the ACSELERATOR RTAC project, hit Edit on the default bay screens, and Bay Screen Builder launches with a live link back — File > Export Package becomes Publish Package, sending the .ldme graphics package straight into the RTAC project. Tag binding then happens in ACSELERATOR RTAC: selecting a label on the published screen auto-highlights its settings row for tag assignment (per AG2024-06).

  • Symbol sets: ANSI or IEC, chosen at project creation. Breakers, truck breakers, load-break switches, disconnects (plain, motor-operated, three-position), dynamic Analog/Digital labels, Navigation and Operation buttons, plus static symbols. Whether a symbol is operator-controllable is set in the device's settings software, not in Bay Screen Builder.
  • Dynamic coloring: breaker/switch symbols carry a Close/Open/Alarm color scheme — Red-Green-Amber, Green-Red-Amber, or Black-White-Gray — and a preview State (Closed/Open/Alarm) for design-time checks.
  • Confirmed operation: Operation buttons (Axion BCU via ACSELERATOR RTAC only — QuickSet-configured devices don't support them) have Confirmation Screen Enabled, 40-char prompt text, and a Critical Action flag that turns the YES button red. Pressed and disabled color states are separately settable.
  • Validation: the Project Analysis pane lists errors/warnings and a Constraints Summary; a project must satisfy all symbol constraints to be exported (invalid ones can still be saved).
  • Alarm screens the AG2024-06 way: paired digital labels per signal (Alarm text bound to the status tag, Normal text bound to NOT the tag — only one renders), timestamps split into seven INS virtual tags with the dateTime_t_Deconstructor function block in CFC logic, analog labels bound to each piece. Publish, map, go online.

Axion hardware, EtherCAT I/O, and touchscreen module details live on the Axion page in atlas.

8Publishing, versions & runtime hygiene

  • RTAC Connections (in Diagram Builder) uploads, downloads, and deletes HMI project files on the RTAC by IP + credentials. From firmware R152 the web interface can do it too: Device Management shows and updates the HMI Runtime binary; Project Management > HMI Project Upload lists, uploads (.hprjson/.hprz), and downloads project files.
  • What operators see: uploaded projects appear under the HMI tab named by the project's Navigation Link Text; one diagram is the project default. Check the running runtime version from the HMI settings gear (HMI Version:) or Device Management.
  • HMI settings can be pinned: attach an HMI runtime settings file to the project and set Enforce HMI Runtime Settings to stop operators changing them; Settings Presets (JSON in %APPDATA%\SEL\AcSELerator\DiagramBuilder\Presets) standardize control colors and properties across an organization.
  • An HMI firmware upgrade via MOT file erases the loaded RTAC project — resend it afterward. From R143, firmware updates carry the matching .binz automatically.

9Performance & gotchas

The expensive controls, per SEL's own table: Conductor, Rotating Fan, and Trend Control are Very High impact; anything animation-enabled (breakers, annunciators, shapes, images, status labels) is High; metering labels are Moderate; plain outputs and static symbols are Low. These are design guidelines, not hard limits.
  • Browsers: Chromium-based (Chrome 40+, Edge 13+, Opera 27+ per Table B.1) rendering in HTML5 — the default on firmware R134+. HTML5-only controls (Multi Image, Rotating Fan, role-secured projects) need R141+. Keep browsers current; a browser update can change HMI behavior.
  • Trend budget: ≤ 4 traces per trend, and typically ≤ 8 trends per project — prefer multiple traces on one trend over many trends, spread static trends across diagrams, and soak-test for days before commissioning.
  • Poll only what you need: request-group intervals, analog deadbands, device poll rates, and total tag count all load the RTAC; an RTAC busy with automation tasks serves the HMI slowly. On Axion systems, an overloaded task (EtherCAT processing regularly over 500 µs) shows up as poor web HMI performance.
  • Concurrent sessions degrade big projects — the Dashboard's Allowed Web Connections caps them. A Low Performance mode in the HMI browser settings sheds CPU load, useful when driving the RTAC's own local display.
  • Misconfigurations cost cycles: nonexistent tags or type mismatches between the Diagram Builder and RTAC projects hurt performance and light up in Debug Mode; use the Project Report to find them. Enable lazy loading of diagrams for big projects (skips diagrams not tied to alarming annunciators).
  • SOE auto-refresh is a load — keep record generation and viewer auto-collection only as fast as the application needs.
  • Tag import/binding lives on the tags page in atlas; the tag database and logic that feed virtual tags are on the logic page.
