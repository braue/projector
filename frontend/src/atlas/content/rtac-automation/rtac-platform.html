RTAC Platform & Project Anatomy

What an RTAC actually is — the model family, the 3530-4 hardware, the real-time engine and its watchdogs, and how a SEL-5033 project turns devices into one tag database

☰The rules, stated plainly

Platform

  • An RTAC is a protocol converter and data concentrator: client connections poll IEDs southbound, server connections answer SCADA northbound, and everything meets in one tag database, moved by the Tag Processor once per task cycle.
  • One SEL-5033 project per RTAC. A full project send restarts the RTAC and every protocol session; a logic-only send does not — but always finish with a full send.
  • Watchdogs are layered: the Application watchdog quietly restarts a dead task; the RTE, OOM, and System watchdogs load the default project, deassert all contacts, and light ALARM.
  • The FID string (SEL-3530-4-R156-V0-Z000079-D20260312) is the version truth: R changes = new features, V changes = point release (fixes/security only).

1What an RTAC is, and which one you have

The Real-Time Automation Controller is SEL's substation computer: an embedded SEL Linux box (with real-time preemption patches) running a protocol engine plus an IEC 61131 logic engine, configured entirely by one ACSELERATOR RTAC (SEL-5033) project. The manual's own application list is the job description: port switch, protocol gateway, SCADA data concentrator/RTU, logic processor, time-sync source, security gateway, synchrophasor processor. One SEL-5033 install configures the whole family; the hardware differs in form factor and headroom:

  • 3555/3560 serial nuance: the built-in DB-9s (COM 1/COM 2) do not support Mirrored Bits — only ports on SEL-3390S8 expansion cards do.

2Hardware anatomy: the SEL-3530-4

Communications

  • 2 rear Ethernet (ETH 1/ETH 2), 10/100, RJ45 or 100BASE-FX/LX10 fiber options; independent interfaces. Defaults: ETH 1 = 192.168.1.2, ETH 2 = 192.168.2.2, front ETH F = DHCP.
  • Front USB Type B — programming only. Fixed IP 172.29.131.1; the SEL USB driver makes it look like Ethernet to the PC. Never two RTACs on one PC, ≤3 m cable.
  • 4 serial DB-9 (COM 1–4), software-selectable EIA-232 or EIA-485/422, 300–115200 bps, nonisolated. Pin 1 can source +5 Vdc (500 mA total, all 4 ports); pins 4/6 carry demodulated IRIG-B out (COM 1 jumpers swap these to DTR/DSR).
  • IRIG-B: BNC input (modulated 2 kΩ / 500 µs, or demodulated 1.5 kΩ / 250 ns) and demodulated BNC output. Drive math: BNC out ≈25 Ω drives ~20 SEL relays (≈2500 Ω inputs) in parallel; a serial-port IRIG out ≈500 Ω drives ~5. With no external source the RTAC generates IRIG-B from its own clock (settable via SNTP/NTP/PTP).

I/O, power, alarm

  • IN101 (terminals A01/A02): one optoisolated input, not polarity dependent, ac or dc. Software pickup 17–265 V, dropout 15–238 V (must be <90% of pickup), delays 1–30000 ms — set delays to ride through the ac waveform when sensing 120 Vac.
  • OUT101 (A03 NC / A04 common / A05 NO): one Form C electromechanical contact, ~8 ms operate, 30 A make / 6 A carry @ 70°C (dc ratings), MOV-protected. This is the alarm contact — map any combination of self-test/status points to it for a hardwired diagnostic alarm.
  • Power (A07 +/H, A08 −/N, A09 GND): 125/250 Vdc & 120/240 Vac, 48/125 Vdc, or 24–48 Vdc supply options; <30 W; rides through 20–100 ms interruptions depending on voltage.
  • Front LEDs: ENABLED, ALARM, LAMP TEST button, per-port LNK/TX/RX for Ethernet and TX/RX for serial 1–4, plus AUX 1–3. ENABLED dark = no power or invalid project; ENABLED dark + ALARM lit = invalid project the RTAC couldn't auto-reset — factory reset territory.
  • Field-serviceable part: exactly one — the BR1632 clock battery (~10 yr). Firmware and projects load over Ethernet; no local console.

3The software platform: tasks and watchdogs

Everything the RTAC does — protocol sessions, tag moves, logic — runs as tasks inside the Real-Time Engine (RTE) on two configurable processing cycles: the main task cycle (SCADA-speed work) and an optional automation task cycle for high-speed logic, as fast as 1 ms. Cycle times evenly divisible into one second lock to the top of the second. Rules that bite:

  • Size the main cycle at ≥140% of the measured overall task timer (under Tags while online, in µs). An overrun doesn't drop tasks — the RTAC borrows time from later cycles to finish them — but the cycle promise breaks and web/HMI access degrades. Automation-task timers: SEL_RTAC.Application.Automation_System.Total_task_timer in a watch window.
  • Tag values (and controls) update once per cycle. A rising edge triggers a control per cycle interval, so a high→low→high inside one interval is invisible. Keep control operations slower than half the cycle time. (Edge semantics of the DNP oper* verbs: see RTAC Quick Facts.)
  • Cross-task mapping is restricted: you can't directly map tags between the automation and main cycles, and referencing another task's tags in logic fails the cross-task compile check (done at send time, or at save with the option; the CrossTaskData library is the sanctioned bridge).

A separate watchdog microcontroller backs all of this in hardware: if the logic engine hangs, it raises the alarm and halts I/O. Repeated System watchdog timeouts suggest failing hardware or firmware, not settings.

Security posture is baked into the OS: exe-GUARD whitelisting executes only signed, pre-approved binaries (no virus definitions), and Mandatory Access Control pins each service to minimum privilege; unauthorized changes trigger an alarm or a reset to factory defaults per configuration. 4The SEL-5033 project model

ACSELERATOR RTAC stores every project in a local authenticated database service (the "RTAC Database", default server localhost, database RTAC; a shared team server is supported). Factory accounts: admin/TAIL and engineer/OTTER — change them. A project is the complete configuration for one RTAC — communications settings, tags, and logic. Its tree:

Tree itemWhat lives there
DevicesClient and server protocol connections. Client = RTAC polls an IED (source tags); server = RTAC answers a SCADA master/HMI (destination tags). Connection types: serial, Ethernet, multidrop serial, and Ethernet-tunneled (serial-port-server) variants of both.
Tag ProcessorThe mapping grid moving source → destination tags each cycle, plus logging config. Depth: see Tags, Quality & the Tag Processor in atlas.
System › Main ControllerCycle times, task watchdog time, task execution order (put protocol collection before the logic that consumes it)
System › SystemTags / System_Time_ControlDiagnostics and self-test tags; IRIG-B/PTP/NTP time-source and DST settings
Contact I/OIN101/OUT101 names, delays, initial values
Access Points / RoutersTransparent engineering-access paths through the RTAC to downstream IEDs
User Logic / Virtual TagsIEC 61131-3 POUs, GVLs, data types (see IEC 61131 Logic on the RTAC in atlas); virtual tag lists = protocol-typed global tags, 30 lists per project (100 on 3555/3350)
  • Tags are self-describing, IEC 61850-flavored structures. Relay1_DNP.AI_0000.instMag = device_protocol · variable · attribute. An analog carries instMag (live), mag (dead-banded event snapshot), q (quality), t (timestamp), db/zeroDb (deadbands), range/rangeC (alarm limits). Quality and time ride along with every mapped value.
  • Limits: 10,000 tags per device tag type (5,000 on the 3505; Modbus devices allow 30,000) inside the model-wide totals of §1. Create only the tags you need — tag count is the RTAC's main burden metric.
  • Reuse machinery: copy/paste a device (auto-renames, increments the port, drops custom Controller logic), or export devices/POUs as XML templates and re-import them into any project. XML from a newer SEL-5033 isn't guaranteed to load in an older one.
  • Advanced surface: every protocol task exposes POU pins (enable polling, comm status, force IIN bits…) and a Controller CFC block where you can rewire standard task behavior. Powerful, rarely needed, not copied with the device.

5How data flows through the box

Platform anatomy: two client sessions fill the tag database; on each task cycle the Tag Processor fans the same data out to the SCADA server, the web HMI, and user logic simultaneously. ▶ Animated in the HTML edition.

  • The protocol stack is symmetric. Clients: DNP3 (serial/LAN), Modbus, SEL ASCII/Fast Message, IEC 61850 MMS, IEC 60870-5-103, C37.118, LG 8979, CP2179, SES-92, CDC II, Courier, SNMP, EtherNet/IP. Servers: DNP3, Modbus, SEL FM, MMS, IEC 60870-5-101/104, C37.118, LG 8979, SES-92, CDC II, (S)FTP, EtherNet/IP. Peer-to-peer: GOOSE, Mirrored Bits, NGVL, PRP. Fieldbus: EtherCAT.
  • Ethernet uniqueness rules: a client connection is keyed by remote IP + port; a server connection by client IP + local port (unless anonymous clients are allowed). Multidrop serial: one physical port shared by many client devices, each with its own server address.
  • Engineering access rides the same box: access points + routers give transparent paths through the RTAC to any connected IED — one Ethernet drop serves SCADA, settings work, and diagnostics.

6Project lifecycle: edit → send → restart → online

The lifecycle loop with a moving cursor. A full send passes through the restart; the amber path is the logic-only shortcut for iterative testing. ▶ Animated in the HTML edition.

  • Save compiles. Ctrl+S syntax-checks and stores to the database; fix output-window errors before sending (double-click an error to jump to it).
  • Send = commit. Full send transfers settings + logic; on completion the software auto-enters online mode. The restart is why a protocol disabled during a send only re-enables after the RTAC comes back with the new settings — and why MMS buffered-report bookmarks (entryIDs) are cleared on download. Budget it: ~2.5 min to ENABLED on 3530/3530-4/2241, ~45 s on a 3555, plus downstream session re-establishment (10–15 s per Axion module on first EtherCAT configure).
  • Logic-only send ("Send only custom IEC 61131 logic") skips the reset for live logic iteration — but protocol settings are silently not sent, so always finish with Send Complete Project; that's also what makes the project readable back out of the RTAC later.
  • Going offline changes nothing — the project keeps running. Forced tags prompt to unforce on exit; an inactivity disconnect unforces them automatically.
  • Read pulls the running project off an RTAC into the database — the recovery path when the backup is missing. Projects can also be exported (.exp), backed up en masse, compared (same firmware version required), and converted to a newer firmware version or a different RTAC type.

7Firmware, versions, and licensed options

Read the FID string from the web Dashboard: SEL-3530-4-R156-V0-Z000079-D20260312 = model · R-number (standard release — new functionality) · V-number (point release — fixes/security only, typically every 3–4 months) · Z-number · date code. Each standard release gets point-release maintenance for at most two years.

  • Software ↔ firmware coupling: the SEL-5033 version listed with a firmware release is the minimum; newer SEL-5033 always works with older firmware. Projects are created for a firmware version — upgrading the fleet means converting projects.
  • 100- vs 200-series: from R154, the 3350 and 3555/3560 get a parallel 200-series firmware on a 64-bit OS (more per-process memory, post-2038 clock). New models (2241-2) are 200-series only. One-way doors: 100→200 upgrades can't be downgraded, and R200/R201→R202 can't go back.
  • Upgrading: load the .upg package from SEL-5033 (RTAC Firmware Update, TCP 5433) or the web interface's Device Management tab; a .zip package changes the MOT/part number. Mid-upgrade the RTAC drops to SELBOOT — ENABLED dark, ALARM lit — then reboots clean. Never pull power during it, and never upgrade with the factory-reset jumper set.
  • Licensed options ride the same mechanism: IEC 61850 GOOSE/MMS support is a factory-assigned licensed option; adding it later means a firmware update plus a licensed-option upgrade file from SEL. The web HMI is likewise an orderable feature that can be added after purchase; Continuous Waveform Streaming is a licensed option too. The 3505/3505-3 can't have the HMI or MMS client at any price.
