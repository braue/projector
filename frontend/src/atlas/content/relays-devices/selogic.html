☰The rules, stated plainly

SELogic in general

  • Every SEL relay is programmed the same way: Relay Word bits (element pickups, timeouts, inputs, outputs, latches) combined by SELogic control equations that feed the trip, close, output, and event logic.
  • Two generations in the field: classic (SEL-351 series — one-line equations, =, six operators, no math) and free-form (SEL-751/751A and 400 series — :=, edge triggers, comparisons, math, comments).
  • Timer units differ by generation: the SEL-351 sets SV timers in cycles; the SEL-751/751A set them in seconds. Check before you copy settings between platforms.
  • Latch bits (LTnn) are nonvolatile and burn flash writes; SELogic variables/timers (SVnn) are volatile and reset on power loss.
  • Equations are processed in a fixed order every ¼ cycle — logic later in the order (SVs, outputs) lags logic earlier in it (trip) by one interval.

1The vocabulary: Relay Word bits

A Relay Word bit is a single logic result — logical 1 (asserted) or logical 0 (deasserted) — updated once per processing interval. The Relay Word is the collection of all of them, organized in rows of 8 bits that you can inspect live with the TAR command (or front panel Targets menu). Every protection element, input, output, and internal function publishes its state here, and SELogic equations consume nothing else.

Time-overcurrent elements uniquely expose three states: pickup (51P — above pickup, timing), timeout (51PT — curve timed out, the bit you trip on), and reset (51PR — fully reset). Trip on the T bit; supervise unlatch with the pickup bit.

Same-precedence operators evaluate left to right. Edge operators apply to individual Relay Word bits only, never to parenthesized groups — on both generations.

Edge triggers are what keep the event report trigger alive: ER = /51P + /51G + /OUT103 (351 factory) fires a fresh report on each new assertion. Without the /, a still-asserted 51P would mask the later breaker-failure OUT103 edge. The 751/751A equivalent: ER := R_TRIG IN101 OR R_TRIG IN102 (the 751 ships with ER := R_TRIG 51P1P OR R_TRIG 51G1P OR R_TRIG 50P1P OR R_TRIG 50G1P OR R_TRIG 51N1P OR R_TRIG CF). NOT R_TRIG x is legal (751/751A) as long as NOT comes first.

The SEL-351 manual's dedicated breaker-failure scheme, live: initiate pulse arms a seal-in, fault detectors hold it, and the SV timer converts persistence into a backup trip. If the breaker clears in time, 50P1/50N1 drop and the seal-in releases before SV7PU expires. ▶ Animated in the HTML edition.

4Timers: pickup and dropout

Every SELogic variable SVnn drives a timer with two settings: pickup (SVnnPU — the input must stay asserted this long before SVnnT asserts) and dropout (SVnnDO — SVnnT holds this long after the input deasserts). An input pulse shorter than the pickup time produces nothing.

Pickup/dropout timing: the first pulse dies inside the pickup delay; the sustained assertion produces an output delayed by PU and stretched by DO. ▶ Animated in the HTML edition.

Volatility: SV variables and timers reset to logical 0 on power loss (all platforms) and, on the SEL-751/751A, on any settings change too. On the SEL-351 a settings change or group change retains SV states — which is exactly what creates the group-change race in Section 8.

5Latches and counters

Latch bits — LTnn

Each latch control switch has two SELogic inputs — SETnn and RSTnn — driving Relay Word bit LTnn. Reset wins if both assert. State is nonvolatile: retained through power loss and settings changes (though an output contact mapped to a latch still de-energizes while power is off, then restores). SEL-351: LT1–LT16; SEL-751A: LT01–LT32; SEL-751: LT01–LT64 (enable count with ELAT).

Classic SCADA toggle (351 factory pattern — one pulsed contact alternately enables/disables reclosing):

SET1 = /IN104 * !LT1
RST1 = /IN104 * LT1
79DTL = !LT1 # drive-to-lockout when disabled

Counters — SCnn (SEL-751/751A)

Up/down counters (IEC 1131-3 counter block; 32 on the 751A, 64 on the 751): SELogic inputs SCnnR (reset), SCnnLD (load preset SCnnPV), SCnnCU/SCnnCD (count up/down, rising-edge); outputs SCnnQU (count reached preset), SCnnQD (count = 0), and the analog value SCnn usable in comparisons. Input precedence: R > LD > CU > CD. Counters live in volatile memory — power loss zeroes them. SCnnCD := NA disables the counter entirely.

Latch flash budget: latch states are written to nonvolatile memory on every change, and the memory has a finite write life — the SEL-751 and SEL-751A manuals both allow an average of 70 cumulative latch state changes per day for a 25-year service life (exceeding it can end in a flash self-test failure). SETnn/RSTnn must never produce continuous cyclical latching; qualify them with timers. The same warning applies to settings-group changes on the SEL-351: about one group change per day average for 25 years.

6Math equations and the memory-register trick

Free-form platforms add math variables (SEL-751A: MV01–MV32; SEL-751: MV01–MV64; enabled by EMV; 400 series: PMV/AMV). Results are stored as 32-bit fixed point — 24 integer bits, 7 fraction bits, 1 sign — range ±16,777,215.99, clipped at the limits. Internally values scale by 128 with rounding at each operation, so order matters: MV01 := (60/4160) * 100000 reports 1562.5 (the tiny quotient rounds first), while MV01 := (60 * 100000)/4160 reports 1442.3. Multiply before you divide, and scale fractional constants up. (SEL-751 firmware R500-V0 and higher switches MVs to IEEE 754 binary32 floating point, range ±3.4e38 — the ×128 ordering trick no longer applies, but float rounding on large products does.)

Relay Word bits used in math count as 0/1 — which gives you if/else in one line (751/751A manual example):

MV01 := 12 * IN101 + (MV01 + 1) * NOT IN101 # 12 while IN101 high, else increment each pass

AG2010-17 builds a whole toolbox from that one shape on SEL-400 series relays. The basic memory register — hold an analog when a control bit drops:

ASV245 := 3P > AMV245 # new maximum seen?
AMV245 := 3P * ASV245 + AMV245 * NOT ASV245 # max-demand register
  • FIFO buffer: chain registers AMV252 := AMV251 * pulse + AMV252 * NOT pulse … — and write the last register's equation first, because freeform evaluates top-to-bottom and each equation must read its neighbor before it updates.
  • Search / integrating timer / signal switch: same pattern; a variable may be assigned several times in the list — the last assignment processed is what is reported. Integrating timers belong in protection logic, whose interval is a fixed fraction of a cycle, not in automation logic whose interval floats with load.

8Gotchas: processing order, races, group changes

  • Everything runs in a fixed order, every ¼ cycle (351 App. G Table G.3): inputs/acquisition → latches → torque control → overcurrent elements → trip logic → close/reclose → SELogic variables/timers → output contacts → display points → settings-group control → ER → Mirrored Bits transmit. A bit computed later in the order isn't seen by earlier logic until the next interval.
  • SVs are processed after TR — tripping via an SV bit (like the factory TR := ... OR SV01) adds up to ¼ cycle. Negligible for most schemes; know it exists.
  • Group-change race (351): SV states carry through an active-group change and are evaluated once by the new group's equations before being recomputed. If Group 3 has TR = SV7 + ... and SV7 happened to be asserted at the changeover, you trip on the first pass. Use the same variables for the same purpose in every group, and test group transitions for mission-critical logic.
  • Element budgets are real: 15 elements per equation on both platforms (spill into an SV as an intermediate); the 351 additionally caps 486 elements + 54 edge operators per group; on the 751A, everything after # is comment and \ continues a line.
  • Equations live per settings group (751A protection logic; 351 all SELogic) — a scheme that works in Group 1 does not exist in Group 2 unless you copied it there.
  • Counters and edge triggers interact with the interval: R_TRIG/F_TRIG outputs and pushbutton _PUL bits last exactly one processing interval — logic in a slower engine (400-series automation) or downstream of the order can miss them.
