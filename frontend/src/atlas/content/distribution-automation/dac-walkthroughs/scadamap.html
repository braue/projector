SCADA point map

Every SCADA point the Adapter blocks can expose: what it means, how it's linked, and how controls must be sent.

§29DA Lib / DA Adapter 105.0.1.100Code-derived

The rules, stated plainly

  1. A point exists only if it's linked. Unlinked points are simply absent. For a feature's enable/disable pair, both points have to be linked, or the feature stays at its setting default (§02).
  2. Status points (DAC → SCADA) are single-point binaries (SPS). Analogs are measured values (MV). Controls (SCADA → DAC) are read from DNP control points (DNPC).
  3. An enable/disable pair on two separate DNP control points responds only to Pulse On. Latch On/Off and Close/Trip on those points are ignored. If an enable from SCADA seems to do nothing, check the operation code the master sends first.
  4. A pair sharing one point uses Close for the first command of the pair and Trip for the second. The first command differs by block. See the table below, because for feeders Close means Exclude.
  5. Single controls (Reset, Return to Normal, Outage Reset, Heartbeat) accept any operation code.
  6. Commands from SCADA are latched until the DAC processes them. Reset is ignored while DA is in progress (§02).

Code caveat With device-definition indexes on two separate points, the scheme's Include and Exclude are cross-wired. The Include command reads SCADA_SchemeExcludeCmd_Index and the Exclude command reads SCADA_SchemeIncludeCmd_Index. A Pulse On to the point defined as "Exclude" therefore includes the scheme, and the reverse. Shared-point mapping, extension pointers and tag functions are wired correctly. Test this on any project that maps scheme include/exclude as two indexed points. ADP/DA_CONTROL.InitDaScadaLink
