Execution: turning the plan into operations

The execution engine re-evaluates the whole plan every scan and only issues an operation when the electrical state makes it safe. It is a set of interlocks, not a timed sequence.

The rules, stated plainly

  1. Isolation opens go first. Non-load-break switches are only opened once dead.
  2. A tie is closed only when exactly one side has a source and that side is live and the other side is dead (or, for closed transition, both sides have sources of the same source group).
  3. Before any close, every device that will be fed through it must already be in the settings group for its new source; the DAC changes settings groups first and waits.
  4. A switch that is "to open" (not isolation) opens after the tie that replaces it has closed (make before break), or straight away if it separates a source from a now-dead area.
  5. Nothing operates while another operation in the same area is in progress, while a permissive request is outstanding, or on an inhibited/abnormal device.
  6. If not finished within ReconfigTimeLimit, the sequence aborts as a restoration failure.

Order within each scan

  1. Opens: isolation switches (load-break: open; non-load-break: open only when disconnected from every source); any switch-to-open already disconnected from every source; with closed transition, other switches-to-open when their tie (CloseTransitionSwitch) shows closed, when OverrideCloseTransition is set, when one side has a source and the other has neither a source nor pending operations, or when neither side has a source. AutomaticReconfig/ExecuteSolution/class_ExecuteSolution.OpenSwitch
  2. Substation bus-restoration switches.
  3. Phase-discrepancy corrections.
  4. Closes, first pass honouring upstream isolation still in progress; if nothing is in progress and nothing is inhibited, a relaxed second and third pass to break circular waits.
  5. RTN and connector feeder checks (settings groups, auxiliary commands).

ClosedTransition is hard-coded TRUE in the manager, so the make-before-break path is always active. OBJ/DA_MANAGER_AR

Closed-transition safeguard

When a tie closes in closed transition, the paired switch carries the tie's index in SW.CloseTransitionSwitch. Every scan, once the tie shows closed, the paired switch is commanded open. If that open command fails and the tie can break load, the DAC opens the tie again to back the loop out. If the tie never closes or its command fails, the pairing is dropped. Equipment/EQUIPMENT

Auxiliary checks before a close

  • Settings group: walking from the restoring source through closed equipment and the switch to close, every SG-capable, not-inhibited device must show the group configured for that source (SRC_A/SG_A … SRC_F/SG_F). Wrong ones get SG.Control[n] (the SSn outputs) and the close waits.
  • Source reversal: devices that need preparing for reversed power flow get REVERSE_SOURCE and the close waits for SourceReversalReady.
  • Remote pending: a connector on the path with an auxiliary command still pending on the remote DAC.
