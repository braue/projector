Restoration planning: how a solution is chosen

After isolation, the DAC searches for a set of opens and closes that re-energises the most load without overloading anything, then ranks candidates by a fixed list of criteria.

§13DA Lib / DA Adapter 105.0.1.100Code-derived

The rules, stated plainly

  1. The inputs are roots (points beyond which load is dead and must be restored), the isolation list (must open) and the return-close list (must close).
  2. Candidates are built by choosing a switch inside the dead area to split it at, and a normally-open tie beyond that split whose far side reaches a valid, live, armed source.
  3. A candidate is thrown out if any rule in the reason-code table below fails.
  4. The best surviving candidate is chosen by: least temporary-limit overload → shed least important load → least load left dead → least normal-limit overload → least load on Level-1-only sources → fewest operations → least load on non-preferred sources → least load moved to a different source group → most load back on its normal source → most margin.
  5. The best executable candidate is always executed, even if it restores only part of the load. Partial restoration sets CapacityLimit and RestorationFail.

The search

class_ArSelector runs a best-first search over a frontier of partial solutions (states). AutomaticReconfig/ReconfigPlanning/Classes/class_ArSelector

  1. Initial state = all isolation opens + all required closes. A switch whose feeders are abnormal with mode None on both sides is left out.
  2. Expand roots: for each root, walk the dead area through closed equipment. Every closed, controllable switch found (not inhibited, isolation allowed, not already chosen to close) is a candidate sectionalising point, as is the root itself. If the walk reaches a SOURCE, the area is still connected to a source and that root produces nothing.
  3. For each sectionalising point, walk beyond it to find open, controllable switches not already in the state whose far side reaches a valid source (rules below) on a feeder with no detected overload and with restoration allowed. Each one produces a child state: + open(sectionalising point) + close(tie).
  4. Load shed expansion (only when the state has a temporary-limit violation, or shedding a less important load is possible): open shed-permissive switches on the overloaded path, least important priority first.
  5. Alternate-source roots (cascading transfers) are expanded only after the ordinary roots have been tried.

The search stops early when the best executable state is Satisfied (executable, positive normal margin everywhere, nothing shed) and more than 10 states have been checked, or the frontier is empty after at least 2. Hitting a limit ends the search with the best found so far.

Interpretation Because every expansion adds one open and one close, solutions that split the outage among several alternates are built up one tie at a time. A large, highly meshed system can hit the 100-state limit; the result is still the best of what was examined, not necessarily the global best.

Ranking (mAR_CompareStates)

A candidate replaces the best so far if it wins on the first criterion where the two differ by more than the deadband (0.01 A; margins 0.2 A). Empty, non-expandable or non-executable states always lose first. AutomaticReconfig/ReconfigPlanning/Helper/mAR_CompareStates

When the best so far overloads a temporary limit

  1. Higher minimum temporary margin
  2. Less total temporary overload
  3. Higher shed priority value (sheds less important load)
  4. Less load left to shed
  5. Less max load on any one Level-1 source
  6. Less total load selected on Level-1 sources
  7. Fewer switching operations
  8. Less max load on a non-preferred source
  9. Less total load on non-preferred sources
  10. Less load moved to a different source group
  11. More nodes restored by their normal source
  12. Higher minimum normal margin
  13. Higher total normal margin

When the best so far is within temporary limits

The candidate must also be within temporary limits. Then:

  1. Higher shed priority value
  2. Less load left to shed
  3. If the best overloads a normal limit: higher minimum normal margin
  4. Less max load on any one Level-1 source
  5. Less total load selected on Level-1 sources
  6. Fewer switching operations
  7. Less max / total load on non-preferred sources
  8. Less load moved to a different source group
  9. More nodes restored by their normal source
  10. Higher minimum normal margin

"Non-preferred" sources are those with Preference ≥ 1: DAC connectors and circuits fed by a shared bus with an event in progress in a neighbouring DAC.

Code caveat Two criteria from the manual's list are disabled in this build: "maximise load restored" (TotalLoadToRestore, disabled 2020-10-26) and "prefer restoring from the same feeder" (TotalLoadRestoredByDifferentFeeder, disabled 2019-06-13), both because the calculations break when the outage area is split. Load restored is still driven indirectly through "less load left to shed".

Source groups, voltage levels, permissives

  • Source group (SourceGroup on circuit or transformer; circuit 0 inherits the transformer's) identifies sources that may be paralleled. It is only enforced where a MatchSourceGroup flag exists: overload transfers, remote events (as copied from the remote DAC), closed-transition RTN. Dead load being restored after a fault is marked 65535 ("was de-energised"), so any source group may pick it up (open transition by nature). At execution, a close between two live sides always requires equal groups.
  • Level 1 / Level 2: by default an alternate is used only at Live2. AllowSelectLevel1 lets the solver choose a Live1 feeder (penalised in the ranking); AllowRestoreLevel1 lets it actually close onto one. Select without restore: the plan is made but the close waits for Live2 and may end with VoltageLimit.
  • Permissive: if a source feeder's Permissive is FALSE, the close onto it waits while the DAC pulses RequestPermissive to that circuit (command retries/timeout as any command).
  • TransferDepth (Adapter default 2, Lib default 0): the number of open boundaries (feeder hops) the DAC may cross when polling neighbours and when checking that an outaged branch has any possible restoration source. 1 = directly adjacent feeders; 2 = also a cascading transfer through a second feeder. AutomaticReconfig/ReconfigPlanning/Helper/fb_RestorationSourceCheck
Code caveat The restorability check crosses an open switch only while depth < TransferDepth. With TransferDepth = 0 no tie can be crossed, so every outaged branch is classed NonRestorable-Branch and nothing is restored through a tie, unless the hidden global g_BypassDepthCheck is set (which raises the limit to 20). The code comments call this out for "legacy projects that have TransferDepth = 0". Projects built on the raw Lib default should be checked; Adapter projects default to 2.

Capacity and margin

Each equipment has a normal and temporary rating (Capacity, TempCapacity; lines inside switch FBs default to 9999 A on the A side, B-side lines use the device's capacity). Margin = rating minus calculated current. For each restoring source the scenario's minimum margin along every path is computed; the scheme minimum and totals feed the ranking. Load is allocated to line sections by LoadAllocation weights between metering points. DG output is excluded from margin.
