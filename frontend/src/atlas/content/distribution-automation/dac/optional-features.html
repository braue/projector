☰The rules, stated plainly

Options

  • Interconnects extend the scheme past one controller — but local sources are always preferred over remote, and several capabilities stop at the boundary.
  • Redundancy is hot-backup pairs running identical projects, both polling. Give each controller its own DNP server session on every device.
  • Pseudo breakers and spare breakers patch gaps in the model where a real device cannot be polled or is swapped in and out.
  • Loops and DG are supported but bounded. Several ordinary capabilities are unavailable on looped sections, and the DAC's DG handling is not anti-islanding protection.
  • A device operating without a fault indication is a manual operation — no event. That is what makes UFLS invisible to the scheme, deliberately.
  • Simulation mode decouples a modeled device from the field so a scheme can be exercised without anything physical moving.

1Scaling past one controller: interconnects

The interconnect shares capacity, availability, fault-indication, and live/dead data between control areas so a solution can reach across the boundary. (Animated in the browser.)

Redundancy

  • Hot-backup pairs, up to four, run identical projects with both controllers polling.
  • Give each controller its own DNP server session on every device — two controllers sharing one session is not the arrangement.
  • Active selection is by RTU voting or a SCADA watchdog.
  • Operator setpoints synchronize automatically between the pair, so a change made on the active controller is not lost at a switchover.

3Loops and distributed generation

Loops

  • Up to three feeders can be explicitly loop-configured.
  • Directional fault indicators are required everywhere in the loop.
  • Fault isolation and restoration work on looped sections.
  • Not available on looped sections: open-phase detection, loss-of-source handling, overload mitigation, and RTN.

Distributed generation

  • DG is modeled as an interconnection recloser.
  • The DAC assumes DG stays disconnected in its solutions, and can close-block the point of interconnection.
  • It is not anti-islanding protection. That responsibility belongs to the interconnection protection itself — see DER Interconnection.

5Commissioning simulation

The commissioning HMI's simulation mode decouples a modeled device from the field: statuses latch, toggles come from the HMI, automatic restoration “operates” the simulated device, and nothing physical moves. This is how a scheme's decision logic gets exercised end to end — every fault location, every abnormal condition, every capacity edge case — without an outage.

Simulation is the FAT for a restoration scheme. Walking every fault position through the model, and every abnormal condition through each feeder, is work that can only be done cheaply here. Doing it in the field means real switching. See FAT & SAT.
