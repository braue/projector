DAC — Event Sequence

Idle → Update → Analyze — what each step does, which devices are polled, every exit back to Idle

☰Core facts

  • New events are detected only on Armed feeders, but can be detected during any step — Idle, Update or Analyze.
  • The Update step has a minimum duration as well as a limit.
  • An abnormal condition found in Analyze aborts the sequence and sets Abnormal Failure at feeder and scheme level.
  • Isolation switches open on event confirmation, in Analyze, before any solution exists — for permanent fault and miscoordination only.
  • This sequence restores nothing. It confirms, isolates, and hands off to reconfiguration.

1The sequence

Per-feeder event sequence. Confirmation goes to the scheme-wide reconfiguration sequence; this sequence returns to Idle immediately. ▶ Animated in the HTML edition: one pass through to reconfiguration, one that times out in Update.

2Idle step

The sequence is forced to Idle whenever the feeder is not armed. Armed and idle, it runs three jobs on interval: integrity polls, abnormal condition monitoring, and new event monitoring. Overload detection also runs only here — see Overload.

Returns to Idle when

  • Analyze determines the event cleared without intervention — reclosing cleared a temporary fault.
  • An abnormal condition is detected during Analyze.
  • Event confirmation is not received within the analyze timeout.
  • The reconfiguration operations triggered by the event complete.
  • A device on the event feeder times out during Update.

3Update step

Entered on a new event on an armed feeder. It completes an integrity poll of all related devices, so later decisions rest on current data, and it identifies unresponsive devices.

Devices polled

  • Devices on the event feeder.
  • Devices on adjacent feeders, and on feeders adjacent to those — governed by the system transfer depth.

Not the whole scheme. On a large scheme this is a fraction of the devices.

Duration

MinimumUpdateTime — 10 sFloor. The step waits this long even if all polls return instantly. It exists for devices that trip straight to lockout — high-set overcurrent, underground systems — so field readings settle.
UpdateTimeLimit — 120 sCeiling. The step ends when all related devices have answered and the minimum time has passed, or when this limit is exceeded.
EffectFor most event types the confirmation item — a lockout, or the open-phase delay — takes longer than the minimum update time, so the floor has no effect.

Timeout behavior depends on device location

Device that timed outResult
On the event feederSequence returns to Idle. Update Timeout alarm asserts. Nothing is attempted.
On an adjacent feederSequence proceeds to Analyze. That feeder is marked abnormal from the communications alarm and is excluded from every solution. The event is still acted on.

4Analyze step

Runs when Update completes. It determines whether a permanent fault has occurred, an open-phase condition exists, or a persistent overload exists.

FindingResult
Abnormal condition on the feederSequence aborts to Idle. Abnormal Failure alarms set at feeder and scheme level.
Event condition no longer existsSequence returns to Idle. No alarm.
Nature of the event cannot be determinedStep exceeds AnalyzeTimeLimit (default 120 s), returns to Idle, sets Analyze Timeout.
Event confirmedAffected sections identified and reported to reconfiguration. Isolation switches commanded open immediately. Sequence returns to Idle.

Affected sections can be

  • Zones downstream of a fault or open-phase condition.
  • Zones upstream of a fault, dropped by a miscoordinated trip.
  • Zones containing overloaded equipment.

For a permanent fault the step also names the switches to open for isolation, and any upstream switches to close to correct a miscoordination.

Isolation is sent before the solution exists. For permanent fault and miscoordination, the DAC sends Open commands to the isolation switches as soon as the event is confirmed in Analyze. Those switches appear in every candidate scenario, so they are sent early. Isolation opens therefore appear in the SOE ahead of any solution.

Open-phase isolation is not unconditional — whether the affected zone is isolated is a setting. See Open Phase & Loss of Source.

5Events during events

  • A new event detected during Idle, Update or Analyze re-enters Update so the new condition is polled in.
  • On the first lockout indication, the DAC forces an update poll of every device on the event feeder, so multiple lockouts are seen and considered. See Permanent Fault & Miscoordination.
  • Reconfiguration starts only when all feeders' sequences are in Idle. Simultaneous events are solved together.
  • A close-onto-fault detection or a directional fault discrepancy immediately aborts any DA sequence in progress.
