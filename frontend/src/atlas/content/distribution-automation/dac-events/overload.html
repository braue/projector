Overload and load shed

Two current levels per device, timed confirmation, and optional load shed. Disabled entirely when any DAC connector exists.

§10DA Lib / DA Adapter 105.0.2Code-derived

The rules, stated plainly

  1. Level 1 = above normal Capacity; Level 2 = above TempCapacity. Each must persist EventDetectTime to be detected.
  2. Level 1 confirms after OverloadConfirmTime1, Level 2 after OverloadConfirmTime2.
  3. Confirmation makes the whole overloaded feeder a candidate for transfer, using closed-transition switching (same source group only).
  4. With load shed enabled, Level 2 for ShedConfirmTime allows shedding load by priority.
  5. No new overload is detected during a DA sequence or for 30 s after one.

Detail

  • Device detection uses filtered current vs. rating, 10 s reset delay, and is blocked while either side of the device is Dead (stale current) or the device is out of service. Transformer/bus overloads count for every feeder on that transformer/bus. Equipment/Overload/Detector/EQUIPMENT_OVERLOAD_DETECTOR
  • The feeder polls devices periodically while overloaded (half the remaining time, between 60 s and IntegrityPeriod). Feeder/Event/Overload/FEEDER_OVERLOAD
  • Overload.New (the event trigger into UPDATE) fires 60 s before a confirm timer expires (2 s if the confirm time is ≤ 60 s), again 120 s after confirmation if the overload is still there and nothing is in progress, and when the shed timer expires. The overload confirms in ANALYZE once a confirm timer has run out.
  • On confirmation: the feeder source is a root with restore flags on the whole feeder. Without shed, the feeder is flagged MatchSourceGroup, so only same-source-group alternates can take load (load is live, so the transfer must be closed transition). With shed, shed permissives are set instead. Feeder/Event/Overload/mFEEDER_ConfirmOverload
  • The solver treats a root feeder with a detected overload as if its temporary margin were its normal margin, which drives the solution to bring it back under normal rating.
  • Outputs: OverloadWarning (detected), Overload target (confirmed), OverloadTime/Seconds countdown, ShedWarning (L2 confirmed and timing to shed), ShedTime/Seconds, LoadShed target, level None/L1/L2/Shed.
  • DA_LOAD.Priority: smaller = more important (default 9999). A load with priority 0, or any load when shed is disabled, is BlockShed unless its allocation is 0.
Code caveat The Revision_History header still carries the note "Load Shed is in an untested state. Do NOT enable Load Shed until can be fixed." Both Adapter and Lib default it off. DA Lib/POUs/Revision_History
