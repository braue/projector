Loops

While building the actual topology, reaching a node that already has a source assigned is a loop, unless every device on the path has PermitLoop. A loop that persists for LoopConfirmTime (60 s) sets ActualLoop, which makes the feeder abnormal, makes it non-normal, and blocks RTN. New loop detection is suppressed while the DAC is analysing (so the DAC's own closed-transition switching does not trip it), but a loop that existed before analysis stays latched. Feeder/Topology/mFEEDER_BuildActualTopology Feeder/FEEDER

PermitLoop on a circuit is ignored if PermitOp (VVO) is set on it. Directional devices on permitted-loop feeders evaluate faults per direction (FaultAB/FaultBA).

Abnormal restoration modes

Set scheme-wide (AbnormalRestoration on the manager, hidden on the Adapter, default None) and overridable per circuit (DA_CIRCUIT.AbnormalRestoration, default GLOBAL). The mode is a bit field: Feeder/Event/Abnormal/eAbnormalRestorationMode OBJ/DA_CIRCUIT

How the isolation works: abnormal devices met during fault, open-phase or source-event confirmation go on a check list with an "interrupted" flag (it lost power from the event). Before solving, AbnormalRestoration.Fault.Process() takes the mode from the feeders on both sides of the device (the more restrictive one). If the device still shows voltage, the DAC re-checks whether it is really cut off from every live source. It then opens the first controllable switch on each side (flag AbnormalIsolation), marks the zone in between AbnormalIsolateZone (reported as extended outage), and makes the far side of each switch a root if restoration is allowed there. Edges that the mode does not allow restoring get AbnormalBlockRestore on their nodes, and any planned reclose through them is removed. Feeder/Event/Abnormal/class_AbnormalIsolation

Interpretation With mode None, one abnormal device anywhere on a feeder (a single relay in local, a hot-line tag, a comm-failed switch) stops all automatic action on that feeder and removes it as a backup for its neighbours. This is the most common reason a "should have restored" event did nothing. Check FeederAbnormal on every feeder involved, not just the faulted one.
Code caveat In DA_CIRCUIT, the per-circuit override of DetectMiscoordination reads dFEEDER.Fault.DetectMiscoordination := IsolateOpenPhase = ENABLE. It compares the IsolateOpenPhase pin, not the DetectMiscoordination pin. When the circuit's DetectMiscoordination is set to anything other than GLOBAL, the feeder's miscoordination correction follows that circuit's IsolateOpenPhase setting instead. With both left at GLOBAL (the usual case) the scheme setting is used correctly. OBJ/DA_CIRCUIT line ~327
