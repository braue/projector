Modbus on SEL Relays

The server side of Modbus on SEL gear — enabling ports, the 751A's fixed register map region by region, the command registers, SET M user maps, and the SEL-735 meter as the contrast case

EMODSLAVEIDSET MBLKMBSET2000hMOD_001–125BADCRC

☰The rules, stated plainly

  • SEL relays and meters are Modbus servers only — they answer, they never poll. The RTAC is the usual client (→ Modbus on the RTAC).
  • The map is fixed and model-specific. SEL-751A puts IA at 650; the SEL-751 puts it at 320. Never carry addresses between models — pull them from your manual.
  • Everything is a scaled integer. Register value × the map's multiplier = the real value. Skip the multiplier column and you are 10× or 100× off.
  • User map: registers 1–125 hold addresses, 126–250 hold values. Poll 126, not 1 — a wall of suspiciously round numbers means you polled the pointers.
  • Output control is deliberate: coils pulse (self-resetting), and LOGIC COMMAND (2000h) is a whole-register write, never a bit operation.
  • The 751A has no Modbus password — it trusts the master. Set BLKMBSET := ALL unless your PLC/DCS is genuinely supposed to write settings. The SEL-751 needs no such guard — its map has no settings region at all; it hardens TCP instead with per-session master-IP whitelists (MODIP1/2). The SEL-735 meter is the opposite: settings writes need the Access Level E password first.

Ports (751A): serial Modbus RTU runs on any of the independent serial ports — front F (EIA-232), PORT 2 (fiber serial), PORT 3 (EIA-232 or EIA-485 by ordering option), PORT 4 comms card (EIA-485 port 4A or EIA-232 port 4C — COMMINF := 232/485 selects, never both at once). Modbus TCP rides the Ethernet PORT 1, up to two concurrent sessions, with the device IP as the Modbus identifier. The SEL-735's Ethernet port supports five simultaneous Modbus TCP sessions on port 502.

2Enabling it: port settings walk-through (751A)

Serial RTU — SET P per port

  • PROTO := MOD — switches the port to Modbus RTU and deactivates SEL ASCII on that port (you lose the terminal there; use another port for ASCII).
  • SPEED 300–38400 (default 9600) · BITS 7/8 (8) · PARITY O/E/N (N) · STOP 1/2 (1) — match the master exactly.
  • SLAVEID 1–247 (default 1) — must be unique per device on the multidrop line; two servers with the same ID is a broken network.
  • Port 4 only: COMMINF := 485 if you wired the 485 terminals.

Modbus TCP — Port 1 settings

  • EMOD := 0–2 — number of enabled Modbus TCP sessions. MODNUM1/MODNUM2 (1–65534, default 502) set each session's TCP port; MTIMEO1/MTIMEO2 (15–900 s, default 15) drop a dead session after that much idle time.
  • Port numbers must be unique across protocols (Telnet TPORT, DNP DNPNUM, SNTP) and must avoid the fixed ports 20, 21, 23, 102, 502 used elsewhere — the relay refuses the save and jumps to the offending setting. MODNUM1 and MODNUM2 may equal each other.
BLKMBSET — set it before anything polls. Global setting, three values: NONE (factory default — all setting changes allowed via Modbus/DeviceNet), R_S (blocks restore-to-factory-defaults only), ALL (blocks every settings write). SEL's manual warns in as many words: under conditions like a PLC/DCS reboot there is a strong possibility the master pushes default settings into the relay, overwriting yours. If the master shouldn't write settings, BLKMBSET := ALL. (751A/DeviceNet-family setting — the SEL-751 has no BLKMBSET and nothing for it to protect: no Modbus-writable settings exist in its map, §3 callout.)

  • Scaling: register × multiplier = system value. The manual's own example: register 651 (IA angle) reads 300 → 30.0° (×0.1). Energy pair: MWH3PO HI at 690, LO at 691, concatenate then ×0.001.
  • Relay Word rows two ways: FC 03 on 1805+ returns the row as a register (bits packed low byte, e.g. ROW_0: bit 7 = ENABLED, bit 6 = TRIP, bits 5–0 = target LEDs). FC 02 exposes the same bits individually at discrete address row × 8 + bit, rows 0–119 = addresses 0–959, numbered right-most bit first.
  • Hardware-dependent: the relay only answers for installed cards — AI/RTD/extra-I/O blocks of the map exist only when the hardware does.
Same family ≠ same map — SEL-751 vs 751A, concretely (verified against the SEL-751 IM 2026, Table E.35). The user-map blocks 1–125 / 126–250 match; everything after them parts ways. 751 layout: reset bits at 261 (R/W) and date/time at 270–275, self-test at 280–319 (RELAY STATUS 312), IA at 320 (A ×1), VAB at 335 in kV ×0.01, per-phase power 360+, energy pairs 380+ (MWH3PI HI/LO = 380/381), RTDs 400+, demand 450+, history select 1692, trip/warn 1730–1733, comm counters 1740–1749, Relay Word rows 0–159 at 1760–1919 (rows 160–328 continue at 1921–2089; AG2022-04's worked example: PB05 = row 15 bit 3 → register 1775 reads 8, discrete input 123). What the 751 lacks: any settings region — no settings writes over Modbus, no BLKMBSET, no remote set-to-defaults (its 2001h bit 1 is reserved); user-map pointers accept 280–1981 (751A: 610–1947). What it adds: MODIP1/MODIP2 lock each Modbus TCP session to one master IP (0.0.0.0 = any master); coils extend past RB32 to RB33–64 (set/clear 91–122, pulse from 123) and expansion-card OUTE outputs, with set/clear RB01–32 starting at coil 27, not 30. On the 751A: IA at 650, VAB in V ×1 at 667, rows at 1805+. Every address on this page is 751A unless marked.

4Controls: coils and the command registers

FC 05 coils — everything pulses

Coil addressAction on write FF00hBehavior
0–26Pulse OUT101…OUT504self-resetting — the physical output pulses for 1 second, then the coil clears itself
30–58Set/clear RB01–RB32FF00h asserts the remote bit, 0000h clears it — this pair does latch
59–90Pulse RB01–RB32remote bit asserts for one SELOGIC processing interval, then clears — your logic must catch the edge

Coil 1 is at address 0. A disabled relay answers coil writes with exception code 4 (Device Error). FC 01 reads back the same coil list; FC 02 reads Relay Word bit status instead (§3).

The command registers (2000h region)

  • LOGIC COMMAND (2000h, write-only): bit 0 = Breaker Close, bit 1 = Breaker Open, bit 3 = Return Status select (which FAST STATUS register a 7Dh response carries), bits 4–14 = DeviceNet aux commands. Not a bit operation — the write replaces the whole register, so every output's intended state must be in every write.
  • RESET COMMAND (2001h, write-only): bit 0 = Trip (target) Reset, bit 1 = Set to Defaults (blocked by BLKMBSET := R_S or ALL), bit 2 = Reset Stat Data, bit 3 = Reset Hist Data, bit 4 = Reset Comm Counters, bit 6 = Reset Energy, bit 7 = Reset Max/Min, bit 8 = Reset Demand, bit 9 = Reset Peak Demand. On the SEL-751 the register is named RESET DATA: bit 1 is reserved (no remote set-to-defaults), bit 10 resets breaker-monitor data, and the same bits are also writable at plain register 261.
  • Readback: FAST STATUS 0/1 (2100h/2101h) mirror trip/warn state plus every input and output contact status — poll them after a command to confirm the action landed. FC 7Dh bundles a control write and a status read in one query (that's how the DeviceNet card keeps its heartbeat).

Writing settings (751A, when BLKMBSET allows it)

Any register in the settings regions can be written with FC 06/10 — but the relay only acknowledges; it holds the edits until no further writes arrive for SETTINGS TIMEOUT (4010h, 500–65535 ms, default 750 ms), then attempts the save. If a setting interdependency rule fails, nothing is saved: the Config Fault bit (TRIP STATUS HI bit 12) asserts and ERROR REGISTER (4016h) + ERROR ADDRESS (4017h) say why and where. There is no Modbus password on the 751A — the manual assumes "an intelligent master system" provides the security. SEL-751: none of this applies — its map has no settings registers, so a master cannot save (or corrupt) settings over Modbus at all; the 4010h/4016h/4017h product-info registers still exist at the same addresses.

A command write, end to end: validate → execute → echo → confirm via FAST STATUS. The failure branch returns the function code with its top bit set plus one exception byte — and bumps the matching comm counter. ▶ Animated in the HTML edition.

5The user map in depth (SET M)

The manual's four-step recipe, verbatim in spirit:

  • 1. List the quantities SCADA needs (up to 125), in the order the master expects them.
  • 2. Look up each label in Table E.33 (IA_MAG 650, VAB_MAG 667, P 685, FREQ 689, IAD 1689, ROW_0 1805, …). Valid pointer targets are 610–1947 (SEL-751: 280–1981) — measurement and status space, not settings. Reserved gaps can be mapped too, as RES_xxxx.
  • 3. Load them into MOD_001–125 — via the ASCII SET M command, QuickSet's Modbus User Map screen, or remotely by writing the addresses into registers 1–125 with FC 06/10 (the AG2016-11 pattern automates exactly this from an RTAC).
  • 4. Poll 126–250 with FC 03 or 04. One contiguous block, one poll.
The poll-the-copy trap. SEL calls it out as the classic error: masters polling registers 1–125 get the pointer table back — the values are the fixed-map addresses (650, 652, 667…), which look plausibly like data. If SCADA shows constant round numbers that never move, you are reading the map of the map. Start the poll at 126.

Planning a SCADA poll: one poll can read at most 125 registers, so the user map is exactly one poll wide. Put 32-bit pairs (energy HI/LO, MV H/L) in adjacent slots in the right order, group by type so the client's variation config stays simple, and leave spare slots at the end — appending later doesn't renumber what SCADA already maps. Without a user map, the practical alternative is over-polling a range and discarding (cheaper than many small polls, per AG2015-29) — the user map beats both.

6Reading event history over Modbus

The 751A exposes its last 50 event summaries through a select-then-read window in the Historical Data region:

  • 1746 NO. EVENT LOGS (how many exist) · 1747 EVENT LOG SEL (R/W) — write the event number 1–50 you want. (SEL-751: count at 1691, select at 1692, window 1693–1718 — same freeze/free-run semantics, and its window adds fault location and fault impedance, with a trip-type enum running 0–71.)
  • Then read 1748–1773: timestamp (seconds ×0.01, minutes, hours, day/month/year), EVENT TYPE (enum 0–55: which 50/51/27/59/81/RTD/arc-flash element tripped, or fault type with/without OC trip), EVENT TARGETS (front-panel LED bitmap), fault-time IA/IB/IC/IN/IG, VAB/VBC/VCA, VG, delta/wye, frequency (×0.01), max RTDs.
  • Writing a nonzero selection freezes the window on that event; write 0 to return to free-running mode, where the registers always track the latest event. After a power cycle the window shows the latest event.

That's summaries only — full oscillography still comes via SEL ASCII/QuickSet, not Modbus. (The SEL-735 meter goes further: full SER records and load-profile history are readable over Modbus — §7.)

7The SEL-735 meter: a second map, different rules

Password-gated writes. MID, TID, password, device time, and the user map are settable — but only after writing a valid Access Level E password (default BLONDEL) into registers 70–74 with FC 10h, packed two ASCII characters per register (B=66, L=76 → 16972 in register 70). Writes then land in a temporary copy until you write 0x0001 to Save Settings (76); write 0x0001 to Discard (77) or Drop Access (75) to abandon, and access times out 15 minutes after the last valid write. AG2016-11 automates the whole dance (password → map → save) from an RTAC with the FileIO library. Coils exist too: 0–2 OUT101–103, 3–6 OUT401–404, 7–22 RB01–16, 23–38 pulse RB — physical coils self-resetting, same as the relay.

8Troubleshooting on the relay end

The comm counters tell you which failure (751A registers 1789–1798 · 751: same ten counters, same order, at 1740–1749)

RegisterCounterIt increments when…
1789 / 1790NUM MSG RCVD / NUM OTHER MSGvalid frames for me / valid frames addressed to some other SLAVEID — proves the wire works
1791INVALID ADDRquery touched a register/coil outside the map, or a region this hardware doesn't have → exception 02h
1792 / 1793BAD CRC / UART ERRORcorrupt frames or byte-level errors — wiring, termination, or a baud/parity/stop mismatch
1794 / 1795ILLEGAL FUNCTION / ILLEGAL REGISTERunsupported FC (e.g. FC 0Fh to a 751A) / bad register count in the query
1796ILLEGAL WRITEwrite to read-only or locked registers — the BLKMBSET signature
1797 / 1798BAD PKT FORMAT / LENGTHmalformed queries → exception 03h

Reset them with RESET COMMAND bit 4. FC 08h subfunction 0000h is a pure echo — the definitive "is the channel itself good" test.

Symptom → cause

  • Dead silence: RTU discards bad-CRC and other-address frames without replying. If NUMOTH climbs but NUMRCV doesn't → wrong SLAVEID. BADCRC/UARTERR climbing → serial parameters or wiring. Nothing climbing → wrong port, PROTO not MOD, or Port 4 COMMINF on the wrong interface.
  • Exception 02h on reads that "should work": 0-based vs 4X off-by-one, a register range spanning into reserved space, or hardware-dependent registers for a card that isn't installed.
  • Exception 02h on writes: read-only target or settings locked (BLKMBSET). Exception 04h: relay disabled. Exception 06h: busy — retry.
  • Values wrong by a clean factor: multiplier not applied (×0.1 angles, ×0.01 PF/frequency, ×0.001 energy), or a 32-bit pair read in the wrong register order.
  • TCP session dies mid-shift: MTIMEO (default 15 s) closed an idle session — poll faster than the timeout or raise it.
  • EIA-485 physical layer (751A): four-wire — +TX, −TX, +RX, −RX plus Shield on the 5-pin plug-in connector (terminals _01–_05), wire AWG 26–14 stripped 8 mm. EIA-232 is good to 15 m in low noise; EIA-485 to 1200 m with proper line termination at the receiver. Past ~100 ft where metallic cable isn't appropriate, SEL points at its fiber transceivers (SEL-2800 family).
  • Settings changed by themselves: a Modbus/DeviceNet master wrote them (a rebooting PLC can push defaults). BLKMBSET := ALL, and check ERROR REGISTER 4016h for the write trail.
