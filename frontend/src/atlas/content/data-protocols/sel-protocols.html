SEL Protocols

The native SEL family — ASCII terminal commands plus binary Fast Meter, Fast Operate, and Fast SER sharing one port, and the RTAC client that configures itself

ACC/2ACA5C0Fast MeterFast OperateFast SERFASTOPauto-configDDF

☰The rules, stated plainly

  • Every SEL relay ships speaking this: serial ports default to PROTO := SEL. Point an RTAC SEL client at it and it auto-configures — no point map to build.
  • Two data streams share one port. Short binary bursts (Fast Meter, Fast Operate, Fast SER) interrupt the human ASCII stream and let it resume — SCADA and a terminal session on the same wire.
  • Access levels gate the ASCII side: ACC → Level 1 (view), 2AC → Level 2 (change/control), passwords required. The binary side is gated by settings: Fast Operate is blocked until FASTOP := Y.
  • Fast Meter is polled; Fast SER is the unsolicited event stream. On the RTAC both work out of the box.

1One port, two data streams

SEL protocol is not one protocol but a family that shares a channel. The ASCII stream is the terminal interface — commands and human-readable (or comma-delimited Compressed ASCII) reports. The binary stream carries short, checksummed messages: Fast Meter (solicited metering/status snapshots), Fast Operate (control), and Fast SER (unsolicited sequential-events records). Binary bursts can interrupt an ASCII transfer mid-report — say, a long event report — and the ASCII stream continues afterward. That is how an SEL comms processor or RTAC collects SCADA data every second while an engineer is transparently connected through the very same port. XON/XOFF and CAN flow control act on the ASCII stream only.

One serial port, four kinds of traffic. The relay's long ASCII meter report is paused by a one-second binary Fast Meter poll, resumes, then an unsolicited Fast SER burst and a Fast Operate control ride the same wire. ▶ Animated in the HTML edition.

2SEL ASCII: the terminal protocol

Commands end with <CR> (or CRLF), can be truncated to three characters (EVENT 1 → EVE 1), and are case-insensitive — except passwords. Every relay message is framed <STX>…<ETX> with CRLF-terminated lines. Compressed ASCII variants of selected reports are comma-delimited with a checksum field per line, made for machine parsing (CEV, CHI, CST, CSE…), plus the Level-0 configuration commands ID, DNA, BNA, SNS/ENA that hand a master the ASCII names behind Fast Meter bits and SER points.

Three wrong password entries → the relay pulses SALARM for one second and stays at Level 0. SALARM also pulses on any successful Level 2/C entry (or denial) — SCADA can see who is logging in. Passwords: up to 12 characters, case-sensitive. After T_OUT minutes idle (0–30, default 5, 0 = never) a serial port at Level 2 drops back to Level 0.

3Fast Meter: the binary data plane

All classic binary messages start A5, carry a length byte (total bytes in message), and end with a 1-byte arithmetic-sum checksum. The design goal (AG95-10, 1994) was self-description: a master should never need per-product firmware knowledge. So the conversation starts with configuration messages the master uses to learn what the data messages will contain:

The steady-state loop (AG95-10 recommended usage): on connect send A5C0; fetch each config block it names; fetch names via ID/ENA/DNA/BNA; then poll A5D1 about once a second. Each response carries a status flag byte — bits for power-up, event trigger, self-test warning/failure, settings change. Event bit set? Fetch with A5B2, acknowledge with A5B5. Settings-change bit set? Re-fetch the config blocks — the layout may have changed. Scaling: single-sample channels are magnitude × scale factor; multi-sample channels average odd/even samples into imaginary/real parts, then the config block's calculation blocks define power, sequence, and delta quantities.

Old relays differ. Pre-1994 SEL relays answer A5DA/A5DC (fixed-layout "old" Fast Meter) instead of A5C0 self-description — the RTAC's "Limited Fast Meter for SEL-100/200 series" support covers these.

4Fast Operate: binary control

Control is deliberately awkward to fake. A Fast Operate command is 6 bytes total, and the operate code must be echoed in arithmetic:

Byte(s)ContentSEL-421 example: open breaker W
2A5E3 breaker · A5E0 remote bitA5 E3
1Length (always 06)06
1Operate code — from the A5CE config block31 (open BK W)
1Operate validation = (4 × code) + 1C5
1Checksum84

The A5CE config block lists what is controllable: on the SEL-421, 2 breakers (open codes 31/32, close 11/12) and 32 remote bits (clear 00–1F, set 20–3F, pulse 40–5F). To succeed, all of: valid code, correct validation and checksum, Fast Operate enabled in settings, breaker jumper installed (for breaker ops), relay enabled. If the enable setting is off, the SEL-421 answers the A5CE config request but silently ignores A5E0/A5E3.

  • 751/751A enable: per-serial-port setting FASTOP := Y — factory default is N (on the 751 the Ethernet port's Telnet sessions have their own FASTOP, also N). On an SEL comms processor the paired setting is SEND_OPER = Y; the SEL-421 calls its setting FAST_OP.
  • What controls map to (751A): remote bits RB01–RB32 mirror the master's remote bits directly (the SEL-751's Fast Operate reaches RB01–RB64). The breaker bit is different: setting BR1 pulses the relay's OC bit (trips via the TR SELogic equation) for one processing interval; clearing BR1 pulses CC (closes via CL).
  • Devices with many controls use the alternate block: A5CF config, commands A5E5–A5E9 (open/close/set/clear/pulse) with 2-byte operate codes.

5Fast SER: unsolicited events

Fast SER rides the generic Fast Message (A546) format — 5-byte routing, status byte, function code, sequence byte C0 (single frame), response number 0–3, and a CRC-16. The master turns the stream on; the relay then pushes SER records as they happen instead of waiting to be polled:

Enablefunction 01, target function 18 (unsolicited SOE), plus max SOE records per message (01–20)
→
Broadcastrelay sends function 18: day-of-year, year, ms of day, then per element an index + µs offset, element states
→
Acknowledgemaster echoes the function code with the MSB set (98); relay retransmits until ACKed
  • Function 02 disables the stream; function 05 (ping) pauses unsolicited transfer and the relay re-sends the interrupted message after its ping acknowledge.
  • If the relay loses records it says so — a dedicated SER Record Lost message (empty record with the end-of-record marker FFFFFFFE).
  • Fast Message also runs inbound on the SEL-751: a comms processor/RTAC pushes unsolicited writes into the relay's Remote Analogs (RA001–RA128) — the RTAC side is the Tx UW Messages tab plus "Transmit Fast Unsolicited Write Messaging on Startup".
  • Timestamps are the relay's SER-quality times (index + microsecond offset) — this is the mechanism that gives an RTAC true sequence-of-events time from a serial relay, unlike scan-time binaries.
  • On the SEL-421 all Fast Message / Fast Meter commands are available at Access Level 0 — no login needed for the binary data plane; only Fast Operate has its own enable.

6On the RTAC: the SEL client and auto-configuration

Insert an SEL client (Insert ribbon or right-click SEL_RTAC → SEL → IED series → device → protocol) on any serial or Ethernet port. It is point-to-point — one relay per client connection, no multidrop. Each supported relay ships with a DDF (device definition file): a template containing a superset of every point the device can offer. All tags start disabled; you set Enable = True on just the ones you need (most live on the Meter tab). On download, the RTAC runs autoconfiguration against the live relay and compares — enabled tags the relay doesn't actually have are marked invalid quality.

RTAC auto-configuration: identify, learn the layout from the relay's own config messages, reconcile against the DDF, then settle into polling — with Fast SER events pushed in between polls. ▶ Animated in the HTML edition.

  • Message Settings tab — each row is one poll: Message Name, Message Type, Command, and a Poll Period in ms (0 disables the message). When the same data exist in Compressed ASCII and binary, SEL says use binary: more efficient, more secure, and uninterrupted by transparent engineering access (which does interrupt CASCII polls).
  • Unsolicited Fast SER — Enable_Unsolicited_SER_RX is on by default. Map records either into explicit tags on the Fast Message Unsolicited SER tab (by label, preferably — index order changes with relay SER settings) or let the RTAC match SER labels to enabled binary tags on the Meter tab, so IN_201 gets true event time and state automatically.
  • Controls — add Remote Bit / Breaker Bit tags and link them in the Tag Processor; the RTAC issues Fast Operate to the relay. Requires FASTOP := Y on the relay port.
  • Passwords — Level 1/2 relay passwords live in the client Settings tab (POU pins can rotate them at runtime). Warning from the manual: pin-written passwords are overwritten by the next settings download — read the running project first or you lock yourself out of the relays.
  • Extras riding the same client — Check IED Configuration (periodic CRC/SHA-256 of settings responses, mismatch pin on change), ASCII SER logging into the RTAC SOE log, CHI/CEV event collection (up to 576 CEV records) with optional COMTRADE conversion and collection, engineering access with Ymodem file-transfer detection.

7SEL protocol vs. DNP3 southbound

Take SEL protocol when…

  • The IED is an SEL relay — it speaks this on every serial port by factory default (PROTO := SEL); zero relay-side protocol engineering.
  • You want auto-configuration: no point map to build or maintain; the relay describes itself, DDF tags just get enabled.
  • You want the extras only this client gives: transparent engineering access through the RTAC, event report / COMTRADE collection, settings-change detection, password management, true SER timestamps by label.

Take DNP3 when…

  • The device isn't SEL, or you need multidrop addressing — the RTAC SEL client is strictly point-to-point, one relay per connection.
  • You want standardized report-by-exception (event classes, deadbands, buffered timestamped events) rather than periodic Fast Meter snapshots plus Fast SER.
  • The link goes to a non-SEL master or upstream SCADA — DNP3 is the interoperable choice, and it's what the RTAC serves northbound anyway. See DNP3 Fundamentals / DNP3 on SEL Relays in atlas.

Both can coexist on one relay: SEL protocol on one port for the RTAC, DNP3 on another for a direct master — the 751A runs SEL ASCII + Fast Meter/Operate/SER concurrently with DNP3 LAN/WAN and Telnet on its Ethernet port.

8Troubleshooting & fine print

  • No response at all → port protocol: the relay port must be PROTO := SEL (it's the default — check whether someone repurposed the port for MOD/DNP/MB), speed/data/parity matched (RTAC client can auto-bps), and on the RTAC the language port setting must be English when behind a comms processor.
  • Data flows but controls don't → FASTOP := N (751/751A factory default) blocks Fast Operate silently; the config request still answers, so discovery "works." Breaker ops additionally need the breaker-control jumper.
  • Access-level lockout → three bad passwords pulse SALARM and leave you at =; passwords are case-sensitive (commands aren't). A port left at Level 2 self-reverts after T_OUT idle minutes; on Telnet, issue QUI before disconnecting or the session stays elevated until TIDLE expires.
  • RTAC tags stuck invalid quality → enabled in the DDF but not found during autoconfiguration — wrong device model picked (watch DDF_Configuration_Mismatch: FID string doesn't match the configured type), or the point genuinely doesn't exist in that relay's ordering/firmware.
  • A message never polls → its Poll Period is 0 (disabled) in Message Settings; flex parse messages also wait until autoconfiguration completes before they're sent.
  • Polling stalls during engineering access → expected: a direct transparent connection (or file transfer on the polling connection) blocks all SEL messaging until it closes; plain transparent access interrupts only CASCII polls, not binary. Autoconfiguration and transparent sessions also pause the Check IED Configuration monitor.
  • SER data loss → Buffer_Overflow pin pulses on lost unsolicited SER; ASCII-SER logging pulses ASCII_SER_Logging_Sequence_Restart when the last-known record scrolled out of the report window (chattering bit) — raise the command parameter or fix the chatter.
  • Health counters → per-client POU pins Fast_Meter_Failure/_Count, Fast_Message_Failure_Count, CASCII_Failure_Count and their success twins tell you which of the three streams is failing.
