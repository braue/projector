☰The rules, stated plainly

Controls

  • The relay ignores the CROB's on-time, off-time, and count.
  • A pulse asserts the bit for one processing interval (~2–4 ms). Nothing is held.
  • SELOGIC is what catches the pulse. Contact time comes from relay logic (TRIP equation, TDUR3D, seal-in) — never from the DNP message.
  • Remote bits clear on power loss. Latch bits survive. Latch anything that must persist.
  • 400-series/751 reject a wrong verb with NOT_SUPPORTED. A 351S does not — a bare pulse to its paired breaker point closes the breaker.
  • One control per point at a time. Status feedback lags a second or two — that's the input scan, not a failure.

Data & events

  • The default map is a reference map. Remap by label — not index hunting — to build what SCADA actually needs.
  • Analogs go out as integers: scale with DECPL, deadband applies after scaling (ANADB).
  • Binary inputs are scanned for DNP events at ~1–2 scans per second. SER-registered points carry true timestamps; everything else carries scan time.
  • DNP time sync is a backup, not a source. IRIG-B first; the default (TIMERQ = I) accepts and ignores time writes.
  • Unsolicited reports fire on event count (NUMEVE) or oldest-event age (AGEEVE), whichever comes first.

1Controls: what the relay does with each code

Relay DNP binary output maps expose remote bits (RB01–RBnn), breaker bits (OC/CC per breaker), disconnect bits (89OC01–89CC20 on a 451), and control-only points (target/energy/demand resets). What each code does on the 400-series/751 (fixed, not settable):

Paired points and non-TCC codes: the 3xx series (351S) honors them as the interoperability fallback — LATCH_ON / PULSE_ON pulse the close side, LATCH_OFF pulses the trip side. The 400-series/751 manuals state paired points support only TRIP or CLOSE and reject the rest. Send proper trip/close codes and the question never comes up. On a 451, single OC/CC points also accept latch/pulse codes (each still just pulses the breaker logic bit). Cancel an operation in progress with a NUL/NUL CROB.

The protocol's timing fields never reach the coil. Contact behavior belongs entirely to the relay's own logic — which is why TDUR3D and the trip equation are where you go when a control “succeeds” and nothing moves. (Animated in the browser.)

How a 2-ms pulse becomes a real operation

  • OC/CC feed the TRIP and CLOSE equations. Program OC into trip logic and CC into close logic; the equations drive the contacts, and TDUR3D plus close-logic supervision (52A, seal-in) stretch the momentary bit into a real coil operation.
  • Remote bits feed SELOGIC. The standard pattern is rising-edge into a latch: SET1 = /RB1 * !LT1, RST1 = /RB1 * LT1 — one pulsed RB toggles LT1. Remote bits are volatile (cleared on power loss); latch bits persist. Latch anything that must survive a restart.

Family differences and limits

  • 3xx series is configurable: Global DNP settings BOOPTCC (response to TRIP/CLOSE codes) and BOOPPUL (response to PULSE codes) each select SET or PULSE behavior. With BOOPTCC = SET, a pulse-style trip on OC does nothing — a classic "control succeeds but nothing happens" cause. Check these two settings first when a 3xx ignores controls.
  • 400 series / 751 are fixed per the table — no BOOPTCC equivalent; pulse = one processing interval, always. 451 breaker bits require the BREAKER jumper ON.
  • Max 10 points per Object 12 request (extras return TOO_MANY_OBJS); multiple pulses in one message can collide and return ALREADY_ACTIVE — send controls one at a time, and wait out a point still executing before re-commanding.
  • Feedback is slower than the control. Relays scan binary inputs for DNP events at ~1–2 scans per second (SER-registered points get true timestamps). The 52A confirmation lagging SUCCESS by a couple of seconds is the scan, not a failure.

2Data: sessions, maps, scaling, events

  • Sessions and maps: a 751A runs up to 3 DNP sessions (EDNP), each pairing its own map, master address (REPADR), and relay address (DNPADR); Ethernet sessions add the master IP (DNPIP) and transport (TCP/UDP). A 451 offers three maps for three unique masters. Each session buffers events independently.
  • Remapping is by label, not index. The default map is a reference map of everything (the whole Relay Word is available on 400-series); build a custom map with just the points SCADA needs, in the order SCADA wants.
  • Analog scaling and deadbands: Objects 30/32 default to 16-bit integers, so decimals need scaling: DECPLA/V/M set decimal places (10.14 A at DECPLA=2 transmits as 1014 — keep the scaled value under 32,767 or poll 32-bit/float variations). Deadbands (ANADBA/V/M) apply after scaling. Object 34 lets the master change deadbands at runtime, but they're volatile — lost on settings change, STA C, or power cycle.
  • Default variations are settable per session (DVARAI and friends) so a master that can't request variations still gets the format it expects.
  • Unsolicited: UNSOL enables it, PUNSOL at power-up; reports fire at NUMEVE accumulated events or AGEEVE oldest-event age, with retry counts and an offline timeout. Serial sessions can even dial a modem out to deliver events.

Whenever you touch scaling, re-check the deadband. They are two settings that behave like one. (Animated in the browser.)

3Troubleshooting & fine print

  • Events not arriving: point assigned Class None, deadband too wide, or the event buffer is undersized. Check the class assignment first.
  • Analog dead or twitchy: deadband applies after scaling — changing DECPL silently rescales the effective deadband too. Recheck ANADB whenever scaling changes.
  • Timestamps a second late are the relay's BI scan, not a comms problem. Register the point in SER if the time matters.
  • Object 34 deadband writes don't survive a relay settings change or power cycle. Re-issue them, or set real deadbands in settings.
  • A plain pulse to a 351S breaker point CLOSES the breaker. On the 3xx paired OC:CC point (with the usual BOOPTCC/BOOPPUL = PULSE), every close-ish code — CLOSE, LATCH_ON, and bare PULSE_ON — pulses the CC side. It doesn't fizzle with a status error like it would on a 400-series/751; it issues a close command. Treat a mis-verbed control to a 3xx breaker point as a switching event, not a typo — and bench-test any device before trusting how it handles an off-model code.
