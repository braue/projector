☰The rules, stated plainly

IEC 61850 in general

  • 61850 models data instead of mapping indexes. IEDs are self-describing — a client browses the device and gets named, structured data; no DNP index or Modbus register map to maintain.
  • GOOSE is layer-2 multicast publish/subscribe with no acknowledgments. Repetition is the only delivery assurance: an event triggers a fast burst, then the message repeats forever as a heartbeat.
  • Everything is engineered offline in ACSELERATOR Architect and loaded into each IED as a CID file. An invalid CID stops the protocol on the relay until a valid one is loaded.
  • The subscriber, not the publisher, detects failure: every message carries a time allowed to live (TAL) — when it expires with no new message, the stream is declared dead.
  • Supervise GOOSE like a protection channel. Check quality attributes, alarm on lost streams, and gate trips on channel health.

1The data model in plain terms

A physical device (IED) contains logical devices (folders, grouped by function), each holding logical nodes (LNs) — standardized 4-letter classes that bundle the data of one function, e.g. MMXU (polyphase measurement) or GGIO (general process I/O). LNs contain data objects, which resolve into typed data attributes. A full reference reads like a path:

Attributes are grouped by functional constraint (FC): ST status, MX measurands, DC description, SV substituted value — in Architect you pick the FC first, then drill down. The SEL-751/751A organizes its LNs under five logical devices:

For analogs, mag is deadbanded and instMag is not — putting instMag in a GOOSE dataset makes every value change a state change and floods the network with fast retransmissions. Deadbands are edited in Architect's Dead Bands tab.

2SCL files: ICD → SCD → CID

Substation Configuration Language (SCL) is the XML that moves configuration between tools — including other vendors' tools. Four file types:

.ICDIED Capability Description — what a product can do: LN and GOOSE support. Ships with the tool; pick the version matching the firmware.
.SSDSystem Specification Description — the substation single-line diagram and the LNs it requires.
.SCDSubstation Configuration Description — the whole project: all IEDs, communications configuration, substation description. Architect saves its project as one.
.CIDConfigured IED Description — one instantiated IED with its addresses. This is what actually gets sent to each relay.
The CID is load-bearing. The relay holds one CID file; transfer a new one only when configuration changes. On the SEL-751A an invalid CID leaves the relay with no valid 61850 configuration and the protocol stops until a valid CID is loaded; the SEL-751 (Ed2.1 firmware) ships with a default CID installed and rejects an invalid transfer, reverting to the previous valid CID. Outgoing GOOSE configuration survives power cycles and resets on both.

3GOOSE on the wire

GOOSE (Generic Object Oriented Substation Event) lives entirely at Ethernet layer 2 — no IP, no TCP. A publisher multicasts its dataset to a group MAC address (SEL defaults look like 01-0C-CD-…); every device on the LAN sees the frame and either subscribes or ignores it. There is no handshaking — the publisher never learns whether anyone received it. The whole message fits in a single frame (data field max 1,500 bytes). Subscribers identify and filter streams by multicast address plus the identification fields in the header:

Retransmission: event burst, then heartbeat

Two Architect settings drive the scheme: MinTime (T1) and MaxTime (T0). Quiescent, the message repeats every T0. On an event (any state variable in the dataset transitions), a new message goes out immediately, then retransmits at intervals growing from T1 back up to T0. On the SEL-751A the curve starts at 10 ms and doubles each step until it levels at the CID maximum — e.g. with a 100 ms maximum: 10, 20, 40, 80, 100, 100 ms… Each message carries TAL = 3× the current interval (2× once at maximum) — for that example: 30, 60, 120, 240, then 200 ms. The SEL-751 (Ed2.1 firmware) profiles differently: immediate, then MinTime, MinTime again, 2×MinTime, then MaxTime thereafter — Min 4 ms / Max 1000 ms gives 4, 4, 8, then 1000 ms; the default (and SEL-suggested) MinTime is 8 ms.

The heartbeat-vs-burst rhythm. stNum says "the data changed"; sqNum says "same data, repeat #n". A subscriber seeing sqNum advance with a frozen stNum knows the channel is alive and nothing happened. ▶ Animated in the HTML edition.

Message size: the header runs up to 419 bytes (the user-defined goCBRef/datSet/goID strings dominate). Payload per item: single binary 3 bytes (8 with quality), single analog 7 bytes (12 with quality); 8 binaries + 8 analogs with quality = 160 bytes. SEL recommends always transmitting quality — the Test-mode features of the 61850 protocols depend on it.

  • Receive mapping targets: on the relay, incoming binary stVal lands in virtual bits (VB001…) and analogs (instMag.f) in remote analogs (RA001…); use them in SELOGIC. On the RTAC, incoming points become SPS (binary) and MV (analog) tags under an auto-created *_GRX connection; outgoing tags live under *_GTX.
  • RTAC publishes via a server model: in Architect, edit the RTAC Server Model, add a logical node of class GGIO, and set counts of IND (binary) and AnIn (analog) data objects to size what the RTAC can broadcast.
  • IEC 61850 on the RTAC is a licensed option (separate price adders for MMS client, MMS server, and GOOSE) — verify the unit's part number supports it.
  • Fixed GOOSE is a different animal: SEL-851-style Fixed GOOSE uses the fixed-length format of 61850-8-1 Annex A, is configured in the relay settings software (Grid Configurator/QuickSet) — not Architect — carries 8 digitals + 8 analogs to up to 4 subscribers, and can coexist with regular IEC 61850 GOOSE. The SEL-751 (Ed2.1 firmware) supports it too: 1 transmit / 4 receive messages of 8 digitals + 8 analogs, landing in FGnRBx bits and FGnRAx analogs with per-stream quality bits FGnRQ. Status via the FGS command.

6Network: multicast, VLANs, bandwidth

Multicast means every GOOSE frame floods to every port by default — every IED on the LAN spends cycles discarding messages it never subscribed to. Tagged VLANs confine each GOOSE stream to the ports that need it; that requires a managed switch (e.g. SEL-2730M) programmed to match the VLAN tags the IEDs apply. The 802.1Q tag also carries priority: GOOSE defaults to priority 4 of 0–7 (7 highest) so switches forward it ahead of bulk traffic.

Substation LAN multicast flow: the switch replicates each GOOSE frame to subscribed ports, VLAN tags prune the rest, and no acknowledgment ever returns. ▶ Animated in the HTML edition.

Bandwidth math

Bandwidth = packet size × 8 × f × N where f is transmit frequency and N the number of streams. Worked example (two IEDs exchanging 8 binaries + 8 analogs with quality; 419-byte worst-case header + 160-byte payload = 579 bytes): quiescent at T0 = 1 s → ~9.2 kbps; worst-case burst at T1 = 4 ms → ~2.3 Mbps. Size links for the burst, not the heartbeat — on an ICON WAN circuit (61850-90-1 substation-to-substation GOOSE) that example needs two ~1.6 Mbps VT increments (3.2 Mbps) provisioned in SEL-5051.

7Supervision & failure modes

Because nothing acknowledges anything, health monitoring is the subscriber's job — and yours.

  • TAL expiry is the loss detector. Relay GOOSE command: nonzero TTL and an empty Code column = receiving normally; TTL 0 with TTL Expired = the stream died. (The RTAC does not support the GOOSE command — check its GRX tag quality instead: q reads good when receiving, invalid when not.)
  • Subscribers reject an incoming GOOSE's data when: configuration mismatch (its ConfRev changed — someone reconfigured the publisher), needs commissioning (ndsCom true), test mode asserted, or decode error (format not as configured). Validation keys on source MAC, dataset reference, App ID, and GOOSE control reference — so publisher and subscriber CIDs must come from the same project.
  • Quality attributes travel in the dataset (include them). A 751/751A with an internal self-test failure sets Validity = invalid and Failure = TRUE; on a permanent (latching) self-test failure it squelches GOOSE transmission entirely and discards incoming GOOSE.
  • The Simulation flag in the header marks test-set traffic substituting for a real publisher — part of the standard's test features, alongside the test-mode bit above.
  • Received bits are sticky: virtual bits and remote analogs mapped to subscriptions hold their last state until overwritten, a new CID loads, or the device restarts (STA C). A dead publisher leaves stale values behind — another reason to supervise.
  • Statistics: GOO S n on SEL relays reports accumulated/max downtime, out-of-sequence messages, TTL violations, corrupted messages, and receive-overflow losses per subscription. An RTAC can flex-parse GOO S n on a schedule (e.g. hourly), log changes to its SOE, forward syslog alerts, and raise SCADA flags — turning silent GOOSE degradation into an alarm before a scheme misoperates.
  • Gate trips on channel health. The SEL pattern: publisher sends a heartbeat bit (e.g. 10 pulses/s); the subscriber alarms if the pulses stop (851 Fixed GOOSE example: fewer than 8 of 10 pulses for 2 consecutive seconds) and supervises each received trip bit with AND NOT <heartbeat alarm>.
  • Timestamp accuracy differs by point: on the 751/751A, data attributes tied to SER-report points get SER-accurate timestamps (≈4 ms — ¼-cycle processing interval); everything else is scanned at ½-second intervals. Put GOOSE-critical bits in the SER report.
