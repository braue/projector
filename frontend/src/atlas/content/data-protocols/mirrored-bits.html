Mirrored Bits

SEL's relay-to-relay protocol — eight logic bits mirrored each way, continuously, over a channel the relay itself monitors

TMB/RMBMB · MB8 · MBTROK RBAD CBADTXID/RXIDPOTT / DTTLOO loopback

☰The rules, stated plainly

  • Mirrored Bits is a virtual 8-output-to-8-input connection in both directions between two SEL devices over one full-duplex serial channel. Set a TMB like an output contact (SELogic); use the mirrored RMB at the far end like a control input.
  • The message is sent continuously — every processing interval — whether or not anything changed. That is what lets the relay monitor the channel: ROK (receiving OK, now) → RBAD (outage longer than RBADPU) → CBAD (long-term unavailability over CBADPU ppm).
  • TXID here must equal RXID there, and never set a port's own TXID = RXID (that would let it accept its own looped-back message).
  • When the channel is bad, each RMB falls back to its RXDFLT character: 0, 1, or X (hold last good). For permissive/trip bits, default to 0.
  • Both ends must match protocol variant and baud. MB8 (10-bit characters) for radios, CSU/DSUs and the SEL-2505; MBT only for the Pulsar MBT9600 analog modem.

1What it is, and what it replaces

Mirrored Bits is SEL's direct relay-to-relay communications protocol: each device continuously transmits the state of eight Transmit Mirrored Bits (TMB1–TMB8) and continuously receives eight Receive Mirrored Bits (RMB1–RMB8) from its peer. Where a hard-wired scheme needs an output contact, a run of control cable, and an input at the far end — per signal, per direction — Mirrored Bits gives you eight signals each way on one serial channel, with almost no wiring and with the channel itself supervised by the relay. Typical uses: pilot protection schemes (POTT/blocking), direct transfer trip, remote control and remote sensing, automated sectionalizing, and bus protection via a logic processor.

The steady-state exchange: frames flow both ways every processing interval. When TMB1 asserts (teal), the far end's RMB1 mirrors it after the next good message clears the security counters. ▶ Animated in the HTML edition.

The TMB acronyms grow a channel suffix on multi-channel devices — the SEL-751/751A and SEL-311 family support channels A and B (TMB1A…TMB8A, RMB1B…); the SEL-2100 Logic Processor uses TxPn/RxPn across 15 ports. The channel letter is not part of the wire message, so any Mirrored Bits device can talk to any other with a compatible message format. SEL-2505/2506 Remote I/O Modules extend Mirrored Bits to devices that don't speak it: eight contact inputs/outputs mirrored over fiber back to a relay or logic processor.

2On the wire

A Mirrored Bits message is four characters. Each character carries a start bit, six data bits, one parity bit, and one stop bit (MB / MBT — nine bits per character) or two stop bits (MB8 — a ten-bit character, for channel equipment that counts bits). Within the four characters, each of the eight data bits is repeated three times, and the peer's ID is encoded.

Message and character framing. MB8's extra stop bit makes the character look like standard 8-N-1 to bit-counting channel equipment (radios, some CSU/DSUs).

Data integrity — four checks on every message

  • Character checks — parity, framing, overrun errors reject the message.
  • Redundancy — the three copies of each of the 8 bits must agree.
  • Addressing — the encoded ID must match the receiving port's RXID setting.
  • Timing — at least one message must arrive in the time three have been sent (seven for MB8 on the SEL-751/751A).

ROK asserts only after synchronization plus two consecutive messages passing all checks; it deasserts immediately on one bad message. New bit states then pass through per-bit pickup/dropout security counters (RMBnPU/RMBnDO, 1–8 messages) — a counter of 1 passes every change, 8 demands eight consecutive consistent messages. Counters count messages, not time: 2 counts ≈ 30 ms at 2400 baud but ≈ 8.5 ms at 9600 on an SEL-751/751A.

Message rate and speed

In general a device transmits every processing interval: 8×/cycle in SEL-321/SEL-421-class devices and SEL-2505/2506 modules, 4×/cycle in the SEL-351/SEL-311 families and SEL-2100. The SEL-751 and SEL-751A send as fast as the baud allows below 9600 (15 ms at 2400, 7.5 ms at 4800) and self-pace to 4×/cycle at 9600–38400. SEL-400 series relays have a TXMODE setting — use Paced (P) whenever the peer is not another 400-series relay. Baud runs up to 38400 in SEL-300-series/SEL-2100 (57600 in the SEL-421); use the fastest the channel permits.

Resynchronization

After two consecutive errors a device transmits an attention message containing its TXID, and keeps transmitting it until it receives an attention message carrying its own ID back — proving the loop is whole and fixing which byte starts a message. In a 3–4 device ring the attention message circulates the whole loop; the price is that one receive error anywhere takes down the entire loop, and one-way-only communication is impossible.

Only one port may own each channel — assigning MBA when channel A already lives on another port errors out ("This Mirrored Bits channel is assigned to another port"). RMB states land in Relay Word rows (751A: rows 88/90; 751: rows 92/94) for use anywhere SELogic reaches, alongside status bits ROKA/ROKB, RBADA/RBADB, CBADA/CBADB, LBOKA/LBOKB.

A POTT scheme in four settings (AG96-13)

  • Port at each end: PROTO := MBA, SPEED := 38400, IDs crossed (TXID=2/RXID=1 ↔ TXID=1/RXID=2), RXDFLT := 00000000 so a dead channel cannot permit a trip.
  • Enable the relay's POTT logic (SET).
  • TMB1 := KEY — the permissive-key element now rides bit 1.
  • PT1 := RMB1A (SEL-351/311 style) — the received permission feeds the trip logic, which the local Zone 2 / Level 2 element still supervises. That supervision is why security counters of 1 are normally fine for POTT.

POTT over Mirrored Bits: an in-section fault keys both ends; each relay trips when its own Zone 2 sees the fault AND the permissive bit arrives. A direct transfer trip (DTT) is the same plumbing with the received bit tripping without local supervision — which is why its RXDFLT and security counts deserve more caution. ▶ Animated in the HTML edition.

5Configuring the RTAC

The RTAC speaks Mirrored Bits like a relay but doubles as a gateway: map RMBs to DNP3 points for SCADA, or map SCADA/logic controls onto TMBs for high-speed control of an IED. Add an instance via Insert → Add SEL device → Mirrored Bits Protocol. It is serial-only (EIA-232 or EIA-485/422), strictly point-to-point — no multidrop, no Ethernet — one instance per serial port, as many as you have free ports (Com1/Com2 on SEL-3555/3560 excluded).

Each TMB tag has three attributes: operSet.ctlVal and operClear.ctlVal (rising-edge set/clear — the pin must go low again before it can retrigger) and status (present state). Before acting on RMBs in logic, gate on the POU pin Rx_OK_Instantaneous and/or per-tag validity — SEL's recommended guard against acting on a dead channel. Loopback testing is done online by forcing the Loop_Back_Without_Data POU pin TRUE (auto-cancelled after the Loopback Timeout setting).

6Failure modes, monitoring & testing

The three channel-health bits

BitMeaning
ROKcReceiving OK right now. Drops instantly on: relay disabled, MB not enabled on the port, parity/framing/overrun, RX ID mismatch, message timeout (3 msgs MB / 7 msgs MB8), or loopback enabled.
RBADcAn outage outlasted RBADPU seconds (default 60). Clears when the channel recovers.
CBADcLong-term unavailability exceeded CBADPU ppm (default 1000) — the "channel is quietly rotting" alarm.
LBOKcLoopback OK — good data received from itself during a loopback test.

Combine RBAD/CBAD into your alarm SELogic — an output contact or SER entry to SCADA — so a failed pilot channel gets fixed before the fault that needs it.

Tools

  • COM / COMM command — summary or long report of the last 255 channel outages: date/time, recovery time, duration, and cause (parity, framing, overrun, data disagreement, ID error, timeout…). COM C clears.
  • LOO (loopback) — jumper TX to RX (or loop the channel at any point), then LOO A: the relay temporarily accepts its own TXID. ROK stays down, LBOK proves the path. RMBs sit at RXDFLT unless you add DATA. Defaults to 5 minutes (settable 1–5000); LOO R restores normal operation. Walk the loopback point outward to localize a bad segment.
  • Ping-pong delay test — set far-end TMBn := RMBn, assert the bit, read round-trip from SER; channel one-way delay = (round trip − 2 × back-to-back) / 2.
  • SEL-2505PB — hand-held TMB source for scheme testing without the remote relay.
Classic gotchas: IDs not crossed (TXID↔RXID) — ROK never asserts. Port not configured before plugging in — device "locks up" / port continuously busy. MB vs MB8 mismatch across a radio or CSU/DSU — works never or intermittently. RXDFLT left at XXXXXXXX on a trip bit — a channel failure freezes the last state instead of failing safe. Loopback left enabled — it times out by design, but ROK is down the whole time. Ring topologies — any single receive error resynchronizes (and drops) the entire loop.
